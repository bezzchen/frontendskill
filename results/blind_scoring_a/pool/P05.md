## Decision: Canvas 2D + sprite atlas, DOM chrome, React-free simulation core

**One `<canvas>` renders all 500 nodes; React never touches per-frame state.** WebGL is rejected as the primary renderer; DOM/SVG nodes are rejected outright.

Rationale, by option:

1. **DOM (500 divs) / SVG — rejected.** 500 per-frame transform writes force either 500 compositor layers (memory blowup) or continuous style recalc. This is the architecture that's janky at exactly this scale, worst on mobile.
2. **WebGL (three/pixi/instancing) — rejected at n=500, kept as escalation path.** Instancing shines at 5k–50k nodes. At 500 it buys nothing measurable while costing ~100–150KB gz of dependencies in a zero-dep repo, context-loss handling, and a texture pipeline we'd need anyway. Wrong point on the complexity curve.
3. **Canvas 2D — chosen.** 500 `drawImage` blits from a pre-rasterized offscreen sprite atlas cost roughly 1–3ms/frame on an integrated-GPU laptop; the drift/spring math for 500 nodes is ~0.2ms. That's 60fps with 5x headroom, zero new dependencies, no hydration concerns (canvas paints client-only).

Key structural points that make this hold up:

- **Renderer-agnostic seam**: the simulation engine (`engine.js`, pure JS, no React imports) writes node state into flat typed arrays (x, y, scale, alpha, spriteIndex); the renderer only consumes that buffer. If requirements ever grow past ~2–3k nodes or need shaders, the Canvas2D renderer swaps for an instanced WebGL one without touching simulation, layout, or interaction code.
- **Regrouping without a physics solver**: each node has a `home` target from a layout function (seeded phyllotaxis scatter; grouped mode = 4 category discs). Drift is per-node phase noise; pointer proximity is a radial displacement field; everything eases with exponential/critically-damped smoothing toward `home + drift + pointerOffset`. Regroup = swap targets, springs do the animation — deterministic and cheap, no d3-force.
- **Interaction**: uniform spatial-hash grid for hit-testing and pointer-proximity queries. Selection/filter live in React state (mode, active categories, selectedId only) and are pushed into the engine via methods; the engine never triggers renders. Filter chips, tooltip, and labels are DOM/Tailwind elements overlaying the canvas — accessible for free.
- **Degradation ladder**: DPR capped at 2 (1.5 on mobile); rAF fully paused via IntersectionObserver when off-screen and on tab hide; `prefers-reduced-motion` disables drift and shortens transitions; a rolling frame-time governor drops DPR to 1, then subsamples node count if a weak device trips it. Touch devices get tap-ripple instead of hover proximity.
- **Accessibility/SEO fallback**: canvas gets `role="img"` plus a parallel (visually hidden) DOM list of nodes grouped by category; filter buttons use `aria-pressed`; selection announced via a live region. This list is also the no-JS fallback.
