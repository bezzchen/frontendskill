## Register: S, bounded to the section; page stays Q

The brief's "experience constellation" plus proximity/regroup interaction is a realtime graphical system that interaction materially changes, so I weighed spectacle explicitly rather than defaulting to it. **Choice: spectacle register inside the section only, realized as a 2D sprite field — 3D and shader-as-thesis explicitly declined.** Reasons: the nodes are small logos that must stay legible and individually selectable (perspective and bloom fight both); the rest of the page (project grid, settings form) is Quiet and must not inherit a global ticker, scroll hijack, or theme override. Nothing about the constellation may run when it is not on screen.

## Engine decision: Canvas 2D, zero new dependencies

| Option | Verdict | Why |
|---|---|---|
| **Canvas 2D, single element, sprite atlas, hand-rolled loop** | **Adopt (platform substrate)** | 500 `drawImage` calls from one offscreen atlas is ~1–2 ms/frame on a laptop and comfortably inside budget on mid-range phones with a DPR cap. Hit-testing falls out of the proximity pass for free. SSR-safe with no `next/dynamic` gymnastics (canvas element renders empty on the server; loop starts in `useEffect`). Zero bytes added to a repo that currently has zero graphics deps. |
| Pixi.js 8 (ParticleContainer) | Decline, **escalation path** | Trivially handles 500 sprites but adds ~120 KB gz, a WebGL context, an async `Application.init`, and a shared ticker that runs by default (must be `autoStart:false` and driven from our loop — exactly the hazard the constraint name). Justified only if node count exceeds roughly 3–5k or the design thesis becomes GPU effects (bloom, displacement). Re-verify the v8 API at that time. |
| three / R3F + drei | Decline | 3D engine for a 2D problem; 600 KB+; `useFrame` runs continuously unless demand-mode is managed; adds nothing the brief asks for. |
| Raw WebGL2 instancing | Decline | Batching win is nil at 500; cost is real (context-loss handling, atlas upload, picking). Same escalation threshold as Pixi. |
| 500 DOM `<img>` nodes with per-frame transforms | Decline, **reference-only for accessibility** | Works on a MacBook; 500 continuously dirty compositor layers plus 500 style writes/frame stutters on a mid Android/iPhone and burns battery. Cannot draw constellation links or depth cheaply. Its one real advantage (native focus/click/AT) is recovered by a non-animated DOM mirror. |
| OffscreenCanvas in a Worker | Decline as baseline, noted as lever | Not needed at 500; complicates pointer/React interplay. Available if main-thread contention appears. |

## Adopt-vs-build fit gate (what I checked)

- **React Bits** (171 components enumerated via its catalog listing): closest are `Particles`/`Galaxy` (OGL point fields, pointer parallax only), `Ballpit` (three+gsap physics), `DotGrid`/`MagnetLines` (cursor-reactive grids), `LogoLoop` (marquee), `Dock` (proximity scaling of icons), `OrbitImages`, `DomeGallery`, `InfiniteMenu` (WebGL image sphere). None has per-node identity with selection, filtering, or regrouping. **Reference-only:** `Dock`'s proximity-scaling falloff curve.
- **Fancy Components** (source tree, docs site was returning 500): `physics/gravity`, `physics/cursor-attractor-and-gravity` (DOM bodies under a rigid-body engine, built for tens of items), `image/image-trail`, `image/parallax-floating`, `background/pixel-trail`. **Reference-only:** the attractor concept for pointer proximity.
- **SmoothUI** (full catalog): DOM UI components on Motion/GSAP; nothing resembling a node field.
- **Substrates considered:** d3-force for the regroup (soft clustering + collision) — declined in favor of deterministic target layouts that are overlap-free by construction and zero-dep; GSAP/Motion for tweening 500×4 properties — declined because a second timeline engine would share ownership of node transforms with the simulation, which the architecture forbids. CSS transitions remain fine for the React-owned chrome (chips, detail card), a different concern.

**Outcome: custom build.** Nothing copies in; two ideas are borrowed as reference.

## Architecture

**Ownership (one owner per concern)**
- **Simulation module** (pure JS, typed arrays, no DOM) owns every node's position, scale, alpha. Position each frame = settled target (critically damped spring or exponential smoothing toward `tx,ty`) + drift offset (sum of two low-amplitude sines with per-node phase, evaluated from absolute time) + proximity displacement. Because drift is an additive offset on the settled position, it never fights the regroup tween.
- **Renderer module** owns the canvas: DPR handling, clear, optional neighbor links as one batched path, 500 atlas blits with per-node `globalAlpha`/scale, a single radial-gradient hover sprite. No `shadowBlur`/`filter` per node — glow, if the director wants it, is pre-baked into atlas cells.
- **Frame-loop module** owns the single rAF handle and the gating rules (below).
- **React** owns discrete state only: active category filter, layout mode, selected id, hovered label for the detail card and the accessible mirror. React → sim through an imperative controller in a ref (`setFilter`, `setLayout`, `select`); sim → React only on discrete events (hover enter/leave, select), never per frame. `useEffectEvent` (stable in React 19.2) is the right tool for those callbacks.

**Images and the atlas**
- All 500 sprites live in one offscreen atlas canvas, 64-device-px cells (about 1472×1408 px, ~8 MB — well under iOS canvas memory limits). Rest size ≤ 32 CSS px at DPR ≤ 2 so blits are 1:1; hover magnification ≤ 1.5× is a transient state where mild upsampling is acceptable.
- Because the data has no images, the atlas builder first draws deterministic procedural marks per node (category-tinted glyph/initials derived from id and the site's CSS variables). It exposes a progressive path for real logos later: batched `createImageBitmap` with a concurrency cap, blitting cells as they arrive while the placeholder mark shows. The sim and renderer only know cell indices, so the image source can change without touching them.

**Layouts and regrouping**
- Two deterministic target generators: *constellation* (seeded, jittered scatter with a minimum-distance pass) and *by category* (four anchors laid out by section aspect ratio; nodes packed per cluster on a phyllotaxis spiral, overlap-free in O(n)). Regroup = swap targets; the integrator does the motion with a per-node stagger keyed to travel distance so it reads as a flow, not a snap.
- Filtering = targets for `alpha` and `scale` (non-matching nodes recede to ~0.12 alpha and shrink) and, in cluster mode, an optional target to the periphery. Same integrator, same frame.

**Pointer, selection, hit-testing**
- One pass per frame computes squared distance from the pointer to all 500 nodes (negligible); nodes inside the influence radius get the proximity falloff; the nearest inside a hit radius is the hover candidate. Click selects it. Enlarged hit radius (≥ 24 CSS px) on touch.
- Touch: no hover exists, so proximity attraction is off; tap selects; `touch-action: pan-y` on the canvas keeps page scroll working. Drift, filter, regroup and selection remain the mobile interaction set.

**Pause and idle (constraint 1)**
- The loop runs only while `isIntersecting && !document.hidden && (motionEnabled || dirty)`. IntersectionObserver on the canvas with a small `rootMargin` so it resumes just before entering view; `visibilitychange` listener for tab switches. On resume, `dt` is clamped (≤ 50 ms) so springs cannot explode after a long pause.
- `prefers-reduced-motion: reduce` disables drift and the proximity wave; regroup/filter become a short fade; the loop renders on demand only and parks itself when settled, so the section costs zero frames while idle.

**Degradation (measured, not guessed)**
- Baseline everywhere: DPR cap 2, backing-store area cap, all 500 nodes present (removing half the "experiences" on mobile would change meaning, so count reduction is not a size-based rule).
- Adaptive quality from a rolling frame-time window: tier 0 (links + hover glow, DPR ≤ 2) → tier 1 (no links, DPR ≤ 1.5) → tier 2 (DPR 1, simulation stepped at 30 Hz with 60 Hz draw interpolation) → tier 3 (drift off, on-demand rendering). Tiers only step down, and only after sustained misses, so quality never flickers.

**Theme, SSR, accessibility**
- Palette read from computed CSS variables at init and on a `prefers-color-scheme` change listener; the atlas is rebuilt on theme change.
- The section reserves its height via CSS aspect ratio so the server-rendered HTML holds space (no CLS); the canvas is inert until hydration.
- The canvas is never the only path: filter chips and layout toggle are real buttons; a visually hidden listbox mirrors the 500 nodes (not animated, so no per-frame cost) and drives the same `select`; an `aria-live` region announces the selection; the canvas itself gets `role="img"` with a summary label. Keyboard selection through the mirror is architecturally in scope; the director decides its presentation.

## Verification plan (actual conditions, not proxies)

Headed Chromium via Playwright against `next dev`, with a dev-only frame counter exposed by the loop:
1. Scroll the section fully out of view; assert the counter stops advancing over 1 s. Scroll back; assert it resumes.
2. Tab hidden: open a second page and `bringToFront()` it (real visibility change, not a monkeypatched `document.hidden`); assert the first page's counter stops.
3. Laptop budget: 1440×900 at DPR 2, 10 s of pointer sweeps plus two regroups and two filter changes; p95 frame time < 16.7 ms.
4. Mobile: Pixel/iPhone device profiles with 4× CPU throttling; record which tier engages and p95 after tiering.
5. `emulateMedia({ reducedMotion: 'reduce' })`: counter stays flat when idle; a filter change produces a bounded burst then parks.
6. Correctness: click known node coordinates → expected `selectedId`; after a filter change, all non-matching alphas ≤ threshold within 800 ms; after regroup, every node is within 1 px of its target and no two nodes overlap in cluster mode.
7. SSR/CLS: the server HTML reserves the section height; Lighthouse CLS unaffected.
