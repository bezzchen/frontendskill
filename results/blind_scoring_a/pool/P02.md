A `5.0.0-beta.2` exists on the `beta` dist-tag — stay on 4.5.0.

## 2. Register decision

**W — Expressive**, with a realtime DOM system as the section's single signature idea. The rest of the page stays **Q**.

Spectacle was weighed explicitly because "living system" is an immersive signal: a canvas/WebGL or physics-engine world (matter-js bodies, three.js) would make the graphics structurally central. Declined, for three reasons: (1) the orbiting things are *content* — focusable buttons carrying roles, dates and links that must FLIP into a structured grid, and only real DOM does that without a second copy of the layout; (2) six bodies do not justify a physics or GPU substrate; (3) the repo's motion stack is anime.js alone, and a second engine over the same transforms breaks one-owner-per-concern. The living quality comes instead from a small orbit field with soft mutual repulsion and hand-perturbation, which is cheap in DOM.

## 3. Catalog fit gate (checked live, two independent passes)

Checked: Fancy Components (Gravity, Cursor Attractor & Gravity, Circling Elements, Drag Elements, marquees), Magic UI (Orbiting Circles, Marquee, Icon Cloud), React Bits (Logo Loop, Orbit Images, Circular Gallery, Ballpit, Magnet, Bounce Cards, Infinite Menu — via GitHub source, the site is a client-rendered SPA), SmoothUI (Magnetic Button, Infinite Slider, Expandable Cards, Morph Surface), Aceternity (Draggable Card, Layout Grid, Infinite Moving Cards, Magnetic Button, Floating Dock, Logo Clouds).

Verdict: **nothing fits; custom build on the existing anime.js substrate.** No catalog item covers orbit + drag + same-DOM morph together, and every candidate imports a second engine (motion, GSAP, matter-js + lodash + poly-decomp, three, ogl) that would own the same transform anime owns. Only Ballpit pauses offscreen; none of the orbit components can be dragged or re-seeded from a release; CSS-keyframe orbits (Magic UI, Fancy Circling Elements) own the element transform and so cannot FLIP into a grid.

Reference-only takeaways: Magic UI's orbit transform idiom (`rotate(a) translate(r) rotate(-a)` keeps logos upright), Fancy Gravity's release/fling feel (reproduced with anime's release spring + `container`), Aceternity Layout Grid's shared-layout morph (in-stack equivalent: `createLayout`), Ballpit's IntersectionObserver + visibilitychange gating. Marquees were considered for small screens and rejected: continuous motion on mobile with no structural payoff.

## 4. Architecture

### 4.1 Ownership (one owner per concern)
- **React** owns data, the state machine (`tier`, `mode`, `facet`, `expandedId`), DOM structure (the same six nodes always rendered; keys never change), semantics and focus. React never animates positions.
- **anime.js scope** (one `createScope({ root: stageRef, mediaQueries })`) owns all motion: orbit timer, per-slot animatables, draggables, layout FLIP, offscreen gate. It never sets React state during frames; it reports through callbacks only at gesture boundaries.
- **CSS** owns the structured arrangements (grid templates per facet via `data-mode`/`data-facet` on the stage) and reduced-motion/pointer adaptations.
- Transform ownership is split by **nesting**, never shared: the orbit loop writes the outer `.slot` transform; the Draggable writes the inner `.tile` transform; the layout FLIP owns transforms only while a morph runs (orbit paused, draggables stopped). No two systems ever touch one element's transform.

### 4.2 DOM model
```
section (aria-labelledby)
  SystemControl  — segmented control
  .stage [data-mode=orbit|structured] [data-facet=experience|projects]
    .slot[data-id=…]  × 6  (+ 1 central hub slot)   ← orbit transform / grid item
      button.tile      — draggable trigger+target; content: logo, label, facet-specific detail
```
One stage, three arrangements, same nodes. In `orbit` the slots are `position:absolute` at the stage center and translated by the loop; in `structured` they are grid items. The stage keeps a **fixed height on large screens in both modes** so morphing never reflows the page below it (the layout module does not animate root size).

### 4.3 Orbit system (large screens)
- Pure model in `orbit-model.js` (no DOM, unit-testable): per slot `{ band, R, theta0, omega, wobbleAmp, wobblePhase }`. Position = center + ellipse(R·(1 + wobbleAmp·sin(ν·t + φ)), θ0 + ω·t), with ω ≈ 2π / 60–90 s and slightly different per slot so nothing locks in phase; ellipse aspect < 1 plus a subtle scale and z-index swap when a slot passes "behind" the hub gives depth without 3D.
- Soft pairwise repulsion between slots and a minimum radius around the hub keep things self-spaced (15 pairs — trivial). This is what makes it feel alive: neighbours yield when you drag a tile toward them.
- Integrator: one `createTimer({ frameRate: 60, onUpdate })` writing targets into one `createAnimatable(slot, { x, y, scale, duration ~400, ease 'out(2)' })` per slot. The animatable's easing absorbs discontinuities and gives the "loose" follow. Six transform-only writes per frame; `will-change: transform` only in orbit mode.
- Seeding uses `createSeededRandom` so positions are stable across reloads; radii are normalized to `min(stageW, stageH)` and rescaled on ResizeObserver.

### 4.4 Drag (large screens, mouse and touch)
- `createDraggable(tile, { container: stage, containerFriction, releaseStiffness/Damping tuned, onGrab, onRelease, onSettle })`. Anime handles touch natively, tap-vs-drag (7px touch threshold), click suppression after a real drag, momentum and containment.
- On grab the slot's θ freezes and the repulsion field reads the tile's true position (slot + draggable offset). On release anime's spring carries the fling inside the stage. On **settle**, fold the offset into the orbit: compute the tile's absolute position, convert to polar about the center, assign new `R`/`θ0` to the slot, then `setX(0, true)` / `setY(0, true)` and write the slot transform in the same synchronous block — no pop. Radii outside the band ease back over a few seconds ("it drifts home"). Drag rearrangements therefore persist through a structured round-trip within the session.
- `touch-action: none` lands only on the small tiles; the stage background scrolls the page normally. Draggables are **not created** in the structured tier, so small screens have no scroll dead zones. Dragging is decorative, so no keyboard/single-pointer alternative is required (WCAG 2.5.7 exemption noted explicitly).

### 4.5 Mode morph (the toggle)
`createLayout(stage, { children: '.slot, .tile > [data-detail]', duration ~650, ease 'inOut(2)', enterFrom/leaveTo: { opacity: 0 } })`, driven around a React commit:
1. Pause the orbit timer; `stop()` any active draggable and fold its offset.
2. **Bake**: write each slot's current visual position into inline `left/top` and clear its `transform` (one synchronous pass). Required because the layout module measures with transforms muted — without this the FLIP would start from the stage center.
3. `layout.record()`.
4. `setState({ mode, facet, expandedId })` → React commits new `data-mode`/`data-facet` and facet-specific detail nodes (`display:none` toggles are handled as enter/leave).
5. `useLayoutEffect` → `layout.animate({ onComplete })`. In `onComplete`, if the target is orbit, re-seed slot params from the recorded rects and resume the timer.
Inputs are queued (control inert) while `layout.timeline` runs, because recording mid-flight would measure the target layout, not the visual one. Content differences between facets (role/dates vs "built at" badge) ride on the module's auto-animated properties and enter/leave.

### 4.6 Tiers via `createScope.mediaQueries`
- `orbitCapable: '(min-width: 1024px) and (min-height: 600px)'` — orbit + drag available (touch tablets in landscape included).
- otherwise **structured only**: no timer, no draggables; the toggle still morphs between the two grids; tap activates.
- `reduced: '(prefers-reduced-motion: reduce)'` — no orbit motion (static seeded constellation), drag still allowed (user-initiated) with a plain short release ease, morph shortened to ~180 ms opacity-led.
- `coarse: '(pointer: coarse)'` — 44px minimum hit targets, no hover-only affordances.
Crossing a breakpoint reverts and rebuilds the tier automatically (verified `scope.refresh()` behaviour); mode is forced to structured when leaving the orbit tier and stays structured when re-entering it (no surprise motion).

### 4.7 Pause discipline (constraint, unprompted)
- Offscreen: an IntersectionObserver on the stage pauses/resumes the orbit timer (exact condition, zero cost).
- Document hidden: `engine.pauseOnDocumentHidden` (default true) — relied upon but **verified**, not assumed.
- Both will be tested under the real conditions (section 6), never via a `document.hidden` stub.

### 4.8 SSR / progressive enhancement
The server renders the structured Experience grid (readable without JS, no hydration divergence — all anime code runs in effects). On the orbit tier, the first entrance is a FLIP from structured to orbit when the stage scrolls into view: the system "comes alive" as a signature moment for free.

### 4.9 Cost
No new dependencies. Incremental anime modules via subpath imports: draggable (~9.4 KB gz as unminified source), layout (~11.4 KB gz, plus waapi), scope (~1.7 KB), animatable (~1.4 KB) — roughly 20–25 KB gzipped incremental, hard upper bound 40.9 KB (the entire library minified+gzipped). Per-frame work: six transform writes, no layout reads.

### 4.10 Data model and files (proposed, not created)
Items gain `logo`, `href`, `period`, `role`, `summary`, `at` (project → company), `featured` (the hub), `band`. Files: `components/ExperienceSystem.jsx` (container/state/SSR markup), `components/experience-system/{data.js, orbit-model.js, useSystemScope.js, useLayoutMorph.js, SystemControl.jsx}`, additions to `app/globals.css`, plus `orbit-model.test.js` (node:test) for fold-continuity and repulsion bounds.

## 5. Interaction model

**States**: `mode ∈ {orbit, structured}`, `facet ∈ {experience, projects}`. Orbit tier initial state: orbit. Structured tier: structured/experience.

**Control**: a three-segment radio-style control on the orbit tier — *System | Experience | Projects* (the rest state needs a name and an affordance; silence is not a decision) — collapsing to two segments elsewhere. Arrow keys move between segments; Escape returns to System on the orbit tier. Alternative: two toggle buttons where re-pressing the active one returns to orbit — subtler, less discoverable.

**Arrangements**:
- *System*: companies orbit the central hub (the `featured` project card, with the other two projects collapsed behind it); hover lifts a tile slightly; drag/fling as in 4.4.
- *Experience*: companies settle into a chronological row/list with role and period; the hub docks small to the side; projects show as "built at" satellites or stay collapsed.
- *Projects*: the hub expands into three project cards; company logos shrink into "at Company" badges on their cards.

**Activation** (click/tap/Enter on a tile): "resolve" — switch to the relevant structured facet with that item expanded. Because the node is the same, keyboard focus survives the morph and travels with the element.

**Gestures**: tap < 7px → activate; drag → move/fling, no activation; swipe on stage background → page scroll. A focused tile in orbit holds still so the focus ring never runs away, and the structured states plus reduced-motion provide the WCAG 2.2.2 pause mechanism.

**Edge cases**: toggle mid-drag → stop, fold, morph; toggle mid-morph → queued until complete; resize within tier → re-normalize radii; resize across tier → rebuild (4.6); tab hidden/offscreen → paused; JS off → static structured section.

## 6. Verification plan (actual conditions)
1. Scroll the stage fully out of view (headed Chromium): slot transforms unchanged for 1.5 s, timer paused; scroll back: resumes.
2. Real visibility change (second tab `bringToFront()`): `engine.paused` true, transforms frozen; return: resumes without time jump.
3. Touch (`hasTouch`, iPhone/iPad descriptors): drag moves the tile with `scrollY` unchanged; swipe on background scrolls; tap activates; drag does not.
4. Same-DOM morph: node identity preserved across toggles; recorded rects equal visual rects within 1 px at frame 0 (no jump); stage height constant on large screens.
5. Fold-on-settle: sub-pixel identical tile position across the fold frame.
6. Reduced motion emulated: zero per-frame transform changes; toggles still work.
7. Breakpoint crossing mid-orbit: no leaked `touch-action` styles or document listeners; no duplicate timers.
8. Five toggles in one second → consistent end state, no orphaned inline styles.
9. Keyboard: DOM-order tab sequence, arrow-key control, Escape.
10. Trace: < 1 ms main-thread per frame in orbit, no forced reflows, ~0% CPU when paused. `next build` green; bundle shows only anime subpaths.
