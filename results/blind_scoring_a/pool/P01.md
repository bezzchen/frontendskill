**Conclusion:** no new dependencies are needed. anime.js 4.5.0 natively covers dragging, physics-feeling release, responsive scoping, and continuous ambient motion. Everything below uses only what is installed.

## 2. Core architectural decisions

**D1 — DOM buttons, not canvas.** Six interactive, linkable, focusable logo cards: they stay real `<button>`/`<a>` elements. Canvas/WebGL would destroy semantics and accessibility for zero benefit at this node count. All motion is `transform`/`opacity` only (composited, no layout thrash).

**D2 — One set of nodes, three expressions of the same layout ("transform-over-flow").** The cards never unmount and never leave the document flow. The CSS grid remains the *neutral* state (exactly today's design, and the no-JS/SSR fallback). Every mode is expressed purely as per-card offsets from the card's natural grid slot:

- `field` (desktop default): offsets place cards on loose elliptical orbits around a central hub.
- `experience` / `projects` (structured): primary group's offsets go to zero (i.e., the real grid), secondary group recedes to a compact "dock".
- Small screens: `field` doesn't exist; only structured states, on the natural flowing grid.

This avoids the classic failure mode of switching between `position: absolute` and grid flow: there is no positioning-mode switch at all, responsiveness stays free, and turning JS off yields today's clean grid.

**D3 — Two nested transform layers per card (single-writer rule).** Each card is wrapped as `outer .slot-layer` > `inner .drag-layer` > `<button>`:

- The **outer layer** is written only by the orbit/layout engine (a `createAnimatable` per card — its built-in per-property easing gives the smooth "drift" for free).
- The **inner layer** is written only by its `createDraggable` instance.

Transforms compose by nesting, so the drag spring can still be settling while the orbit keeps breathing underneath — that overlap is precisely the "living" quality — and there are never two writers fighting over one element's `transform` (the main practical risk of combining Draggable with any other animation, including the new `AutoLayout` module, which I therefore recommend *against* using on draggable nodes).

**D4 — React owns structure and state; anime.js owns motion.** React state holds exactly one interesting value, `mode: 'field' | 'experience' | 'projects'`, and renders markup, ARIA state, and content emphasis. Positions never pass through React state — the imperative engine (built once per breakpoint inside a `createScope`) reads refs and animates. Re-renders happen only on mode change.

**D5 — `createScope` with `mediaQueries` is the responsiveness backbone.** One scope with `{ isDesktop: '(min-width: 1024px)', coarse: '(pointer: coarse)', reduceMotion: '(prefers-reduced-motion: reduce)' }`. Scope constructors re-run automatically when any query flips (resize across breakpoint, OS motion setting change), and everything built inside is torn down with a single `scope.revert()` on unmount — the same `.revert()` discipline `IntroFade` already uses (and StrictMode-double-mount safe). This is strictly better than `IntroFade`'s one-time reduced-motion check, since it reacts to runtime changes.

## 4. Interaction model

### 4.1 Desktop (fine pointer, ≥1024px) — the "field"

- The section becomes a **stage** of fixed height (~`min(70vh, 620px)`, constant across modes so nothing reflows on switch). A **central hub object** — a circular "featured project" node (or monogram; open question Q1) — sits at stage center with a slow breathing scale and faint concentric ring.
- The six cards **drift on loose elliptical orbits** around the hub: per-card base angle, angular velocity, ring radius, and radius "breathing" derived from `createSeededRandom(item.id)` so the arrangement is organic but deterministic (stable across reloads, no hydration randomness). A single `createTimer` computes ideal positions each tick; each card's Animatable eases toward them (~400ms `out(3)` follow), which turns the raw math into lazy, fluid drift. Distinct radii + phases keep the six from colliding without any physics sim.
- **Hover:** the hovered card's drift pauses (its target freezes) and it lifts slightly (scale ~1.04, shadow via pseudo-element opacity); the system continues around it.
- **Drag:** grab any card and throw it. `createDraggable` on the inner layer, `container` = stage with soft edges (`containerFriction`), spring release (`releaseStiffness`/`releaseDamping`) for momentum. On `onGrab` the card's orbit-follow is suspended; on `onSettle` the card **rejoins the system from where you left it**: its combined position is converted back to (angle, radius), folded into the outer layer, and the inner layer is silently zeroed with `setX/setY(0, muted)` in the same frame (no visual jump). The user has genuinely rearranged the living system, and it keeps living. The arrangement persists in memory while the page is open (Q4).
- **Click vs drag:** cards remain buttons. `dragThreshold: { mouse: 4, touch: 10 }` plus a moved-beyond-threshold flag consulted by the click handler (set in `onGrab`/`onRelease`) cleanly separates "open this item" from "throw this item".
- **Entrance:** on first mount the cards render in the grid (SSR-safe), then stagger-release from their grid slots into orbit (`stagger(40, { from: 'center' })`) — the intro doubles as proof that grid and field are one system.
- **Idle guards:** the timer pauses when the section leaves the viewport (IntersectionObserver) and when the tab is hidden (anime engine default).

### 4.2 Structured states — Experience / Projects

- A **segmented control** above the stage: `[ System | Experience | Projects ]` (`System` = the field; on small screens the segment is just `[ Experience | Projects ]` since there is no field). Buttons with `aria-pressed`; the hub also acts as a "return to System" affordance in structured modes, where it recedes to a small badge.
- Choosing **Experience**: a `createTimeline` freezes the orbit timer, then FLIPs every card — the three experience cards glide into the clean grid (outer offsets to 0, drag layers reset; a secondary metadata line — role, dates — fades in), while the three project cards **recede to a dock**: scale ~0.6, opacity ~0.5, parked in a tidy row along the stage's lower edge. Staggered ~40ms, spring-ish ease, ~650ms total. **Projects** is the mirror image. Nothing unmounts, nothing is hidden — "same elements, reorganized" is literal.
- **Docked cards stay interactive:** clicking a docked project card while in Experience mode switches to Projects mode, with that card animating to prominence — continuity as navigation.
- **Reordering & focus order:** when the primary group changes, React reorders the items array (stable keys, so nodes move rather than remount) and a manual FLIP (measure rects in the event handler → reorder → invert in `useLayoutEffect` → play with anime) covers the move. DOM order therefore always matches visual/reading order, keeping keyboard tab order honest. Draggable instances survive node moves; `draggable.refresh()` runs after each layout change.
- Dragging is **disabled** in structured modes (`draggable.disable()`) — tidy states should feel tidy; drag re-enables on return to the field.

### 4.3 Touch devices and small screens

- **Small screens (<1024px):** no field, no stage height inflation, no timer, no draggables — the section is the current stacked grid with the two-tab control. Tab switches use the exact same FLIP + recede treatment (receded group compresses into a dock row after the primary list), so the "reorganize" moment is preserved where it matters, at a fraction of the cost. This is also the low-battery/low-GPU posture.
- **Large touch screens (iPad landscape and similar — `isDesktop && coarse`):** the field runs, and drag works via pointer events. Two touch-specific accommodations: `dragThreshold.touch: ~10px` so a finger resting or scrolling doesn't grab a card, and `touch-action: pan-y` on the stage so vertical page scrolling always wins until a deliberate horizontal/held drag engages. Hover states are simply absent (no hover dependency anywhere; hover is decoration only).
- Tap targets: hub and docked cards keep ≥44px hit areas even when visually scaled down (scale the visual, not the hit layer — the button padding lives inside the scaled layer's parent).

### 4.4 Reduced motion

Handled by the scope's `reduceMotion` query (live, not just at mount): no orbit timer, no springs, no draggables; the segmented control still works and mode changes become a ~180ms opacity crossfade with zero travel. This extends the convention `IntroFade` already set, and content/functionality is identical in every mode.

## 5. Performance budget and guardrails

- 6 cards × (1 Animatable + 1 Draggable) + 1 timer + 1 hub animation — trivially within 60fps; anime's single engine loop is the only rAF consumer.
- `transform`/`opacity` only; `will-change: transform` on the two wrapper layers of six cards (12 small layers, acceptable); shadows/hover glow animated via pseudo-element opacity, never `box-shadow` interpolation; no `filter` animation.
- No React renders in the motion hot path; renders only on mode change.
- ResizeObserver on the stage recomputes orbit geometry (ellipse radii from stage aspect); Draggable's own `onResize` keeps containers honest.
- Everything created inside the scope; unmount = one `scope.revert()`.

## 6. Risks and mitigations

| Risk | Mitigation |
|---|---|
| Draggable and engine both writing one element's transform | Structural: two nested layers, one writer each (D3) |
| `AutoLayout`/`createLayout` (WAAPI writer) fighting Draggable | Don't use it on these nodes; manual FLIP (~30 lines) instead |
| Hydration mismatch from random orbit params | Seeded RNG keyed by item id; orbit offsets applied only post-mount; SSR renders neutral grid |
| Click swallowed by drag (or vice versa) on touch | `dragThreshold` per input + moved-flag click guard; verify on real coarse-pointer emulation |
| Page scroll fights drag on tablets | `touch-action: pan-y` + touch threshold; field mode absent on phones entirely |
| Breakpoint flip mid-drag/mid-animation | Scope constructor teardown reverts all instances cleanly; state machine re-enters the appropriate mode |
| StrictMode double-mount in dev | Scope-revert cleanup, same pattern as existing `IntroFade` |
