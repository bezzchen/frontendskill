## Rendering architecture decision — Experience Constellation

**Repo:** `<REPO>`

### Register: W (Expressive), bounded — Spectacle weighed and declined
The brief's vocabulary ("constellation", 500 nodes, drift, pointer response) invites a spectacle register (shader/particle engine as the core). I decline it deliberately: the same brief says *subtle*, *one bounded section*, *smooth on a normal laptop*, *degrade sensibly*; the surrounding page is Quiet (Arial, five CSS tokens, light/dark via `prefers-color-scheme`); and the content is identifiable logos that must stay legible and selectable — a spectacle system would fight that. The section is W with one signature motion idea, **"the constellation regroups"** (a staggered reorganization by category); everything else is micro-motion. The page stays Q.

### Repository facts that constrain the design
- Next 16.2.12 / React 19.2.8 / Tailwind 4.3.3, plain JSX (no TS), App Router, `"use client"` pattern already used in `components/SettingsPanel.jsx`. No `node_modules` (Node 22.14 present; `npm install` needed). Lockfile has 98 packages, **zero** animation/canvas/3D libs.
- `components/ConstellationData.js` already provides 500 items `{id, label, category}` across 4 categories — **no image fields**. Placeholder visuals are required now; a logo asset contract must be defined for later.
- Theming is CSS-token based (`--background/--foreground/--muted/--surface/--line`) in `app/globals.css`; a canvas would have to re-plumb these by hand.

### Fit gate (catalogs checked)
React Bits (Particles/OGL, Ballpit/three, DotGrid/DotField/Canvas, Masonry, ChromaGrid, InfiniteMenu/WebGL2 atlas, LogoLoop, Antigravity…), Fancy Components (Cursor Attractor & Gravity via matter-js, Parallax Floating, Image Trail, marquees), SmoothUI (Logo Cloud blocks, Interactive Image Selector), Paper Shaders (Dot Grid/Dot Orbit — WebGL2-only, no pointer uniforms, single-image textures), drei (Instances/Points/Image/Html), plus react-force-graph-2d, sigma.js + @sigma/node-image, react-icon-cloud, react-bubble-chart. **None supports per-node images + pointer proximity + filter/selection + animated regroup together.** Verdicts: Masonry (images + filter reflow) and Cursor Attractor (images + proximity) → *reference-only*; sigma/react-force-graph → *reference-only* (graph camera/zoom UX and physics engine we would fight; drift needs a custom loop anyway); Paper Shaders → *declined* (backdrop-only, adds nothing to a quiet page). **Outcome: build custom, zero new runtime dependencies.**

### Decision: DOM nodes + compositor-driven motion (no canvas, no WebGL)
Each node is a real `<button>` inside a `<ul>`; motion is executed by the compositor (CSS keyframes/transitions), not by a JS render loop. Evidence and reasoning:

- **Measured headroom.** Headless Chrome 152 with real GPU compositing (ANGLE Metal, M4, DPR 2): JS-driven DOM transforms on 500 nodes = 0.6 ms JS at a locked 60 fps; 1.1–1.5 ms under 4–6x CPU throttling (throttle verified by a calibration loop), still 60 fps; **2000 nodes still 60 fps** (1.3 ms). Canvas 2D matched at 500 (0.5 ms) but **collapsed to 100 ms frames at 2000 with `2d_canvas: enabled`** — an unexplained nonlinear ceiling in the accelerated canvas path that I will not build on. The JS-driven DOM bench is the *worst case* for the chosen design; steady state here is ~0 ms main thread.
- **Main thread stays free inside a scrolling page.** A canvas loop runs sim + 500 draws every frame while visible, competing with scroll on mobile. Compositor animations do not touch the main thread.
- **Accessibility, theming, dark mode, hit-testing, and testability come free** (no shadow-DOM mirror for a canvas, no `getComputedStyle` token plumbing, Playwright can assert positions/styles directly).
- Design-director iteration happens in CSS, not in draw code.

**Ownership (one owner per concern):**
- *React* owns structure and discrete state: items rendered once, filter set, layout mode, selection, tier, a11y (roving tabindex, `aria-pressed`, live region).
- *CSS/compositor* owns interpolation: drift keyframes, regroup/filter/proximity transitions, reduced-motion overrides.
- *Imperative engine* (a hook, typed arrays, uniform spatial grid) owns only high-frequency proximity: on rAF-coalesced `pointermove` it writes `--s` (scale) on the ≤ ~40 nodes within radius and emits discrete `onHover`. Never per-frame React state.
- *Transform ownership per element:* outer node = position + proximity scale (transitioned, written on discrete events); inner element = drift keyframes. Two layers per node; no two engines touch the same transform.

**Layout & positions:** pure, seeded, deterministic `scatterLayout` (jittered blue-noise grid) and `clusterLayout` (per-category phyllotaxis packs, centers sized by count). Positions are emitted as normalized `--nx/--ny` and resolved by CSS `translate: calc(var(--nx)*100cqw) calc(var(--ny)*100cqh)` — SSR renders the field correctly with no hydration mismatch, resize needs no JS, and regroup is one batch of style writes that CSS transitions (900 ms, eased, 0–250 ms stagger).

**Assets contract:** now — CSS monogram "coins" on `--surface` with a `--line` ring (zero requests). Later — an `image` field plus **one 2x raster sprite sheet** (`public/constellation/sheet@2x.webp` + JSON map) applied via `background-position`, loaded when the section nears the viewport, monogram as instant fallback. Not 500 `<img>` requests, not 500 inline SVGs. Color logos sit on neutral coins so they read in both themes.

**Pausing (constraint):** IntersectionObserver on the section + `visibilitychange` toggle a `data-paused` attribute → `animation-play-state: paused` on all drift animations and the proximity listener detaches. Reduced motion: drift off, transitions 0 ms, static highlight only.

**Degradation tiers (drop motion before dropping nodes):** A — fine pointer: 500 nodes, drift, proximity. B — coarse pointer/small viewport: 500 nodes, smaller coins, tap-to-select, `touch-action: pan-y`, drift kept. C — `prefers-reduced-motion`, `saveData`, or a runtime probe showing dropped frames during the first regroup: drift off (static nodes are not even separate layers → zero layer memory); only at `deviceMemory ≤ 2` cap to ~240 stratified nodes with an honest "showing 240 of 500" note.

**Budget:** +0 runtime deps, component ≤ ~8 KB gz, ≤ 2 ms main thread during pointer interaction, 0 ms at rest, ≤ 25 MB layer memory on mobile.

### Rejected alternatives
Canvas 2D (a11y mirror, theming plumbing, continuous main-thread loop in a scrolling page, observed pipeline cliff); Pixi 8.20.1 (~130 KB+ for no gain at 500; shared-ticker/context-loss/SSR complexity); three 0.185 + R3F 9.7 + drei 10.7 (3D unwarranted, 230+ KB gz); sigma.js / react-force-graph-2d (adopting their camera UX and physics). Escape hatch: if node count ever grows past ~2000, replace the field with a WebGL2 instanced-sprite renderer behind the same React/state boundary — the layout and data layers do not change.

### Verification plan (actual conditions — the embedded pane reports `document.hidden === true`, so it cannot verify motion; use headless Chrome via CDP for automation plus a headed run)
1. Offscreen pause: scroll the section out → drift `getAnimations()` report `paused` and node rects are unchanged over 500 ms; scroll back → running. Hidden: bring a second real tab to front, same assertion — no fake `visibilitychange` dispatch.
2. Regroup: category centroids separate; completes ≤ 1.2 s; < 5% dropped frames via a rAF probe.
3. Filter/selection: opacity ≈ .12 and `pointer-events: none` on non-matches; live region text; roving-tabindex keyboard path; axe pass.
4. Proximity: synthetic pointer sweep → in-radius nodes `scale > 1`, others 1; ≤ 1 ms per `pointermove`.
5. Mobile: device emulation + 4x CPU throttle → no frames > 50 ms during regroup; vertical scroll still works over the field.
6. Reduced motion emulation → zero running animations. `next build` clean; route size delta ≤ 10 KB gz.

**Implementation order (next step, after `npm install`):** layout/PRNG pure functions + `node --test` → SSR field with cq-unit positions → filter/regroup via CSS vars → drift + pause plumbing → proximity engine → selection/detail/live region → tiers → verification suite → design-director pass.
