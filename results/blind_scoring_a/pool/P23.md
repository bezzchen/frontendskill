# Experience System — architecture and interaction proposal

Repository: `<REPO>` (Next 16.2.12, React 19.2.8, Tailwind 4.3.3, Anime.js 4.5.0 — all lockfile-pinned; `node_modules` not installed, so every library claim below was checked against the published 4.5.0 sources).

## 1. Register decision (made explicitly, not by default)

**Chosen: S (Spectacle) for this one section on large screens, executed as a DOM system; W (Expressive) for the structured states and for everything below 1024px; the page baseline stays Quiet/editorial.**

Why S applies: on desktop the orbit *is* the section's structure — not a decoration on top of a grid — and interaction (drag, focus, the view switch) materially changes it. That is the guidance definition of the spectacle register, and the brief's "living system" language asks for it.

Why a DOM system and not a canvas/GPU substrate: there are seven interactive, semantic elements (logos and project cards that must stay focusable, labelled, crisp, clickable). A canvas would re-implement focus, hit-testing, text and SR labels for zero visual gain at n = 7, and touch/small screens need a structured DOM layout anyway — one DOM tree serving every state avoids building the section twice. Anime.js is already the engine and drives seven transforms trivially.

Declined explicitly: WebGL/three/ogl (above), a rigid-body physics engine (matter-js: wrong feel for "loosely orbit", five extra dependencies, and a second transform owner), and a second motion engine (motion/GSAP) — see the fit gate in section 5.

Ownership note: `frontend-design` is available here as the design director and was deliberately not loaded for this architectural pass; it should own the visual thesis (how the "system" reads, logo treatment, ring visibility, the core's form, caption typography, motion tuning) when implementation starts. This document owns register, architecture, boundaries, and adopt-vs-build.

## 2. Interaction model

**Elements (the "same elements" in every state):** three company nodes (Company A, Company B, Research Lab), three project nodes (Atlas, Vector, Field), one central object. Following the brief literally — "logos orbit around a central *project* object" — the central object is the **project stack**: the three project cards stacked as one object at the centre.

**Three views, one DOM:**

| View | Company nodes | Project stack | Drag |
|---|---|---|---|
| `system` (desktop default) | orbit loosely around the core; drag enabled; focus/hover hold a node still and lift it | at centre; subtle breathing; click opens `projects` | on |
| `experience` | reorganise into a structured row/timeline in chronological order; role/period captions appear | collapses to a compact core chip ("3 projects", clickable) | off |
| `projects` | gather as small "built at" chips — ideally attached to the project they relate to (needs a company↔project link in the data) | fans out into the 3-card grid | off |

**Control:** a segmented control that is a `radiogroup` (arrow keys, `aria-checked`), not a `tablist` — the same elements reflow, there are no separate panels. Desktop shows three positions (name for the first is the director's call: "System" / "Overview" / "All"); below 1024px, and always under `prefers-reduced-motion`, only `Experience | Projects` exist and `experience` is the default. Changing view announces via a polite live region. Alternative the brief's wording could imply — two tabs where the orbit is the "unselected" rest state and re-clicking the active tab releases it — is discoverability-poor and awkward for assistive tech; listed as owner decision 1.

**Transitions:** every view change is one FLIP animation of the same nodes (position, size, radius/opacity of captions), staggered ~40 ms, 600–800 ms total (director tunes). `system → structured`: the orbit freezes, drag is disabled, nodes travel to their slots. `structured → system`: nodes travel to their *current* orbit positions, then the orbit resumes. Mid-drag view switch: the grab is cancelled first.

**Orbit ("loosely"):** each company node has a ring radius, a slow angular speed (one revolution in roughly 40–70 s, differing per node so spacing evolves), a phase, and a low-frequency two-sine drift (~6–10 % of radius, irrational frequency ratio). Soft constraints: pairwise repulsion when nodes come closer than their sizes plus a margin, an exclusion radius around the core, soft containment inside the stage. Rendered position follows the target with frame-rate-independent damping (Anime `utils.damp`/`lerp` with `dt`-corrected factors from `timer.deltaTime`, `dt` clamped after pauses). Phases and ring assignment come from `utils.createSeededRandom` so the feel is reproducible in tests. The core breathes from the same tick — **one continuous tickable in the whole section.**

**Drag:** grab lifts the node out of the solver (it still repels the others, which feels tactile). On release, Draggable's own release physics run (velocity glide, soft bounce off the stage bounds via `containerFriction`). On settle the solver re-absorbs it: the node's new orbit *angle* is where the user left it (`atan2` from the core), and its *radius* eases back to its ring over ~1.5 s — the system remembers the arrangement but stays coherent. Optional delight (director's call): the tangential release velocity gives the whole system a decaying spin. Short press without movement stays a click (Draggable only suppresses clicks after the drag threshold — 3 px mouse / 7 px touch — verified in source).

**Entrance:** the section server-renders as the structured `experience` layout (no-JS baseline, hydration-safe, reduced-motion final state). On desktop, after hydration and on first intersection, the controller switches to `system`: nodes leave their slots into orbit — the one-time "comes alive" moment — and the orbit starts. If the section is above the fold this runs ~300 ms after first paint.

## 3. Architecture

### 3.1 Rendering approach: transforms on top of CSS layout, one owner per concern

Every view — including `system` — is a real CSS Grid layout keyed by `data-view` on the stage root. The `system` grid is the **orbit at rest** (core centred, company slots at their ring-rest positions). The solver only ever adds live offsets to those rest slots; structured views are pure CSS, so responsiveness and "clean" alignment are free and nothing drifts. On desktop the stage reserves a fixed `min-height` (about `clamp(560px, 72vh, 780px)`) so switching views never changes section height (no CLS, no scroll jumps); below 1024px there is no stage and the grid sizes itself.

| Concern | Single owner |
|---|---|
| Node `transform` in `system` | that node's `Draggable`. The solver never touches styles: it writes through `draggable.setX(x, true)` / `setY(y, true)` (muted callbacks) when the node is not grabbed or settling, so Draggable's internal coordinates never desync and a grab starts exactly where the node is. User input writes through the same instance. |
| Node position/size/caption changes during view transitions | `createLayout` (Auto Layout, WAAPI-driven). Draggables are `stop()`ped and `disable()`d before `record()`, and re-synced after completion. |
| Time | the Anime `engine` (one rAF loop). The orbit `Timer` is the only continuous tickable. |
| Register switching (`lg`, reduced motion, coarse pointer) | `createScope({ mediaQueries })` — verified to revert and re-run its constructors on every `matchMedia` change, so a tablet rotating from landscape (system) to portrait (structured) tears the system down and rebuilds cleanly. |
| Offscreen pause | `IntersectionObserver` on the stage → `timer.pause()` / `resume()`. |
| Hidden-tab pause | `engine.pauseOnDocumentHidden` (default `true`, verified). |
| Structured layout geometry | Tailwind/CSS Grid via `[data-view]`. |
| Semantic state (`aria-checked`, live region, captions) | React state; rendered once per change. No React work per frame. |
| Visual thesis | design director. |

Rules that fall out of this: no second engine anywhere; CSS `transition` is never applied to a Draggable-owned transform (the segmented control's indicator may use CSS or a plain `animate()` — it is not shared); `will-change: transform` only in `system`; React never renders `data-layout-id`/inline transforms (Layout assigns `data-layout-id` itself; stable React keys keep the elements alive).

### 3.2 Why Layout can carry orbit → grid in one call (verified, with one spike)

In 4.5.0 `AutoLayout.record()` measures each node with its inline transform temporarily set to `none` (pure layout box) while also recording the computed transform; for any node whose transform differs between states, `animate()` runs a single WAAPI animation on `translate` (slot delta) *and* `transform` (old matrix → new matrix), then commits the final transform inline. So a node sitting at an orbit offset is carried into its grid slot — position, size, border-radius, caption opacity — by one `layout.update()`/`record()+animate()`. Layout first shipped in 4.3.0 (absent in 4.2.2); docs: https://animejs.com/documentation/layout.

**Spike S1 (half a day, before committing):** the Layout ↔ Draggable handoff. Two things to prove with no visible jump on a `system → projects → system → grab` round trip: (a) after Layout commits a `matrix(...)` inline transform, the next Draggable write composes correctly (4.4.0 changed transform render order and how inline matrices are preserved); (b) `setX/setY` on a freshly re-enabled Draggable positions the node immediately. Mitigation if (a) bites: clear the inline transform on completion, then `reset()` + `setX/setY`. React integration follows the docs' advice for frameworks: `layout.record()` → `flushSync(() => setView(next))` (React 19) → `layout.animate()`, so React remains the single source of truth for `data-view` while Layout measures the committed DOM.

**Plan B if S1 fails:** Draggable stays the sole transform owner in *all* states; structured positions come from measuring invisible per-view slot placeholders (`ResizeObserver` keeps them fresh) and each transition is `draggable.animate.x/y(target, duration, ease)` with staggered durations, plus explicit size tweens for the project cards. Same UX, fewer moving parts, more code for size/caption changes.

### 3.3 Pause policy (constraint 1)

The orbit timer pauses when the stage is not intersecting, when the document is hidden (engine default), during a view transition, and never runs under reduced motion or below 1024px. The engine's rAF loop self-terminates when no active tickable remains (`tickEngine` re-requests only while `engine._head` exists), and Draggable's `updateTicker`/`overshootTicker`/`resizeTicker` are idle unless a drag or resize is in flight — so pausing the timer is sufficient to stop the library ticker. That is a claim to be *measured*, not assumed (section 7).

Anime's `onScroll` ScrollObserver was considered for the offscreen condition and set aside: it adds scroll-driven tickers to derive a boolean that `IntersectionObserver` gives natively and verifiably.

### 3.4 Files (for the implementation phase — nothing created now)

- `components/ExperienceSystem.jsx` — orchestrator (client): header, `ViewSwitch`, stage, nodes; owns `view` state and the controller lifecycle (`useEffect` → `createScope({ root, mediaQueries })`, cleanup `scope.revert()`; StrictMode-safe).
- `components/experience-system/data.js` — items with `href`, `period`, `role`, logo, and the project→company link.
- `components/experience-system/system-controller.js` — scope constructors: the `lg && !reduced` constructor builds Draggables, the orbit timer, the IO, and the Layout instance and returns its cleanup; the structured constructor builds only the Layout for tab switches.
- `components/experience-system/orbit-solver.js` — pure math (`step(dt)`, targets, re-absorb-on-settle), ~100 lines, seeded.
- `components/experience-system/ViewSwitch.jsx` — radiogroup segmented control.
- `app/globals.css` — stage geometry tokens (`--stage-h`, `--node-size`, `--core-size`), `[data-view]` grids, reduced-motion rules.
- Housekeeping: add a `.gitignore` (`node_modules`, `.next`) — the repo has none.

Estimated footprint: 350–450 lines of JS across four files, ~60 lines of CSS, +10–15 KB gzipped of Anime modules over today's `animate`-only import (to be measured with `next build`). No new dependencies.

## 4. Draggable configuration (verified 4.5.0 defaults)

`createDraggable(node, { container: stage, containerPadding, containerFriction (default 0.8), releaseContainerFriction, releaseStiffness 80 / releaseDamping 20 / releaseMass 1 (source values; docs say damping 10), maxVelocity 50, dragThreshold {mouse 3, touch 7}, cursor {grab, grabbing} (fine pointers only), onGrab/onDrag/onRelease/onSettle })`. Draggable raises `z-index` on grab, blocks `selectstart`, suppresses the click after a real drag, and handles `touchcancel` → no stuck grabs. Two side effects to watch in verification: it calls `scrollInView` on grab (must not scroll the page when a node is fully visible) and it has container auto-scroll (`scrollThreshold` 20) — with a non-scrollable stage as `container` this should be inert.

## 6. Touch and small screens

- **< 1024px (phones, portrait tablets):** structured only. `Experience | Projects` radiogroup; switching is a Layout FLIP (crossfade under reduced motion); no drag; no continuous animation, so nothing to pause. Hit targets ≥ 44 px. The central project object becomes the header card of the Projects view — same element.
- **≥ 1024px with a coarse pointer (tablet landscape, touch laptops):** system mode on, drag on. Constraint verified in source: Draggable sets `touch-action: none` on each node and `preventDefault`s `touchmove` once a finger is on it, so a swipe that *starts on a logo* will not scroll the page (its ancestor-scroller check only covers scrollers inside the trigger). The stage, the core and the rest of the page scroll normally; nodes are ≤ ~96 px chips, so the dead zone is small. Also: `-webkit-touch-callout: none`, `user-select: none`, `draggable={false}` on logo images. Owner decision 3 offers tap-only on coarse pointers if this trade is unwanted — one flag in the scope constructor.
- **Orientation/resize:** scope refresh rebuilds the right mode; `draggable.refresh()` and a `ResizeObserver` re-measure slots.
- No hover effects on `(hover: none)`.

## 7. Accessibility

Nodes stay `<a>`/`<button>` in logical DOM order (roles chronologically, then projects) — the orbit is visual only, so tab order is sane. Focusing a node in `system` holds it still and lifts it (solver treats focus like a grab); blur rejoins. Radiogroup for views with arrow keys; live-region announcements; decorative rings/shadows `aria-hidden`. Reduced motion: no system view, ≤ 200 ms crossfades — consistent with `IntroFade`'s existing guard. Drag has no keyboard equivalent by design: the arrangement encodes no information, and every item is reachable and readable in the structured views (documented in code).

## 8. Performance

Per frame: three or four transform writes (company nodes + core), zero reads, zero React. Measurements only on resize/view change. O(n²) repulsion at n = 7 is negligible. `will-change: transform` toggled with the mode. Zero rAF when offscreen, hidden, structured, or reduced-motion. Fixed-height stage → CLS 0 on view switch. Optional `timer.fps = 60` cap on 120 Hz displays (owner decision 6). Anime is modular ESM (subpath exports verified), so only the used modules ship.

## 9. Verification plan (constraint 2 — actual conditions, not proxies)

1. **Offscreen pause:** wrap `requestAnimationFrame` before load; scroll the section fully out; after release animations settle, expect 0 frames over 2 s and `engine.reqId === 0` (dev-only debug hook). Scroll back: frames resume, positions continue without a time-skip.
2. **Hidden tab:** two pages in one Playwright context; `page2.bringToFront()` (headed) makes page 1 genuinely hidden — expect `engine.paused === true` and 0 frames; return → resumes. Not `Object.defineProperty(document, 'hidden', …)`.
3. **Mouse and touch drag** (touch via iPad-landscape emulation ≥ 1024 px): node follows pointer; glides on release; settles; after 2 s the orbit angle equals the release angle within tolerance and the radius has returned to the ring.
4. **Scroll on touch:** vertical swipe on the stage scrolls; on a node it does not (documented) — or does, if decision 3 chooses tap-only.
5. **View switch:** section height unchanged; `layout-shift` entries = 0; final node transforms identity and Draggable `x/y === 0`.
6. **Round trip has no jump:** `system → projects → system → grab`; node rect before and one frame after grab differ < 1 px.
7. **SSR / no-JS:** built HTML contains all six items in the structured layout; page legible with JavaScript disabled.
8. **Reduced motion:** no system option; 0 frames at rest; switches ≤ 250 ms.
9. **Resize:** 1280×800 (system) → 768×1024 (structured, no Draggables, `engine.reqId === 0`) → 1280 (system again).
10. **Keyboard:** Tab order matches DOM; focused node moves < 0.5 px over 1 s while others move.
11. **Grab side effects:** grabbing a fully visible node does not scroll the page (`scrollInView`); dragging to the stage edge does not scroll the window.
12. **Bundle:** `next build` size delta.

## 10. Risks and spikes

- **S1** Layout ↔ Draggable transform handoff (above) — half a day; Plan B ready.
- **S2** `setX/setY` as the solver's per-frame channel — confirm immediate DOM update with muted callbacks; fallback is a custom Pointer Events handler with `createAnimatable` (one owner, drop Draggable).
- **S3** Tablet scroll dead zones on nodes — decision 3.
- Anime.js 4.5.0 is recent (June 2026) and Layout is under a year old (Jan 2026); versions are pinned exactly, and Plan B keeps the design independent of Layout. Do not install `three` (4.5.0's optional peer is for its new three adapter).
- Hydration: all measurement lives in effects; nothing viewport-dependent is rendered on the server.

## 11. Owner decisions (defaults in bold)

1. View control: **three-position radiogroup on desktop** vs two tabs + re-click-to-release.
2. Data: **link each project to its company** so logos attach to their project in the Projects view (only if true to the CV).
3. Tablet drag: **keep drag on coarse pointers** (small scroll dead zones) vs tap-only.
4. Entrance: **animate grid → orbit on first view** vs SSR the constellation at rest (CSS `cos()/sin()`; more complexity).
5. Core idle: **breathing only** vs cycling the top project card every ~7 s.
6. Frame cap: **uncapped** vs 60 fps.
7. Naming and every visual decision: design director.
