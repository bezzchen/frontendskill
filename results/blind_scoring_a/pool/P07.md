# Proposal: Account settings — architecture and interaction approach

Repo: `<REPO>`

## 1. What is there today

Next 16.2.12 (Turbopack default), React 19.2.8, Tailwind 4.3.3 via `@tailwindcss/postcss`, plain JSX with `@/*` paths, one static route. Design tokens live as raw custom properties in `app/globals.css` and are consumed as arbitrary values (`bg-[var(--surface)]`), so there is no accent, danger, success, or focus-ring token and nothing Tailwind can compose. `components/SettingsPanel.jsx` is a single client form with `useState`.

Defects that the polish pass must fix, not paper over:

- Heading hierarchy is broken: the page has `<h2 id="settings-title">` and the panel nests three more `<h2>`s.
- The password input has no label (placeholder only), no `name` (it is never submitted), no `autocomplete`, and no current-password field.
- Name and email have no `autocomplete`, no `required`; validation is the browser bubble only.
- "Save" flips `saved` to true forever: no dirty, pending, error, or revert state, and the submit does nothing. (The persistent `aria-live` region is the one thing done right; keep it.)
- One native checkbox where the brief says "toggles"; hit target ~13px.
- Inputs are ~40px tall; nothing accommodates a mobile keyboard or safe-area.
- Repo hygiene: no `.gitignore`; `components/ConstellationData.js` is unused by the page (leave it, out of scope).

## 2. Register: Q — Quiet / Operate

A settings form is a surface the user comes to, changes one thing on, and leaves. Motion's only job is to confirm state changes precisely. Q defaults to micro-motion and zero new dependencies, and this proposal holds to both.

Spectacle weighed and declined: the brief says polished, accessible, production-ready — no "unforgettable/immersive" signal — and a realtime graphical system would compete with the form's job. Expressive (W) also declined: there is no single concept to serve here. The "signature" of this page is the save-state choreography (idle → dirty → saving → saved → idle) executed exactly.

Decisions:

| Piece | Gate | Basis |
|---|---|---|
| Switch | reference-only → custom | APG "Switch Example Using HTML Checkbox Input": `<input type="checkbox" role="switch" class="peer sr-only">` + styled track/thumb. Native keyboard, label association, FormData participation, and AT state for free; ~20 lines. Radix is the smallest adopt but adds a dependency tree for one control. |
| Validated field | reference-only → custom | shadcn Field/FieldError wiring (`aria-invalid`, `aria-describedby`) and React Aria's "native validation behavior" idea, over the Constraint Validation API. |

| Password show/hide + rules | reference-only → custom | Origin comp-23/51 structure; inline SVG instead of lucide. |
| Animation engine | declined | Every motion is a two-state CSS transition on a discrete state change. Flip condition: if the director asks for a shared-layout morph or spring-drag on the switch, `motion/react` becomes the sole transform owner and CSS transitions come off those properties. |
| Form library (RHF + zod), icons (lucide), toast (sonner), strength lib (zxcvbn) | declined | Five fields; four inline SVGs; inline status beats a toast for a form; strength meter deferred. |

Net: zero new runtime dependencies. Typography can change with zero npm deps via `next/font` if the director chooses.

## 5. Architecture

```
app/page.jsx                              server component: reads settings from the store,
                                          passes initialValues; heading fix (h2 → section h3s)
app/globals.css                           @theme inline tokens mapped onto the existing :root vars
                                          (keeps media-query dark mode) + accent/danger/success/ring,
                                          --ease-out, durations; the spinner keyframe only
components/settings/SettingsPanel.jsx     layout shell; composes the two forms; stateless
components/settings/ProfileForm.jsx       "use client"; useActionState(saveProfile); name, email,
                                          notification switches; dirty tracking; blur validation
components/settings/PasswordForm.jsx      "use client"; useActionState(changePassword); own submit
components/settings/Field.jsx             label + control slot + hint + error; useId; aria wiring
components/settings/Switch.jsx            checkbox role=switch + track/thumb; label + description
components/settings/SubmitButton.jsx      useFormStatus; idle/pending/saved label stack
components/settings/FormStatus.jsx        persistent role="status" region
components/settings/SaveBar.jsx           static row on md+; sticky bottom bar on mobile when dirty
components/settings/actions.js            "use server": validate → persist → revalidatePath → state
components/settings/validation.js         pure validators shared by client and server
lib/settings-store.js                     persistence adapter (httpOnly cookie stub; swap for DB)
```

Data flow: RSC reads current settings → `initialValues` → controlled client form → Server Function validates with the same `validation.js`, persists, `revalidatePath("/")`, returns `{status, values, fieldErrors, savedAt}` in the same response → form syncs its dirty baseline to the returned values.

Two independent forms, not one: saving your name must not require a password, and "Profile saved" vs "Password updated" gives precise status. Password action never persists or logs the password; the stub accepts any non-empty current password (no real verification exists) and enforces the new-password rules.

Two freshness gotchas designed around: React resets uncontrolled fields after a successful action, so all fields are controlled (do not "simplify" to uncontrolled later). Next bundles its own React canary in the App Router, so `<ViewTransition>` may exist — not used; stable APIs only.

## 6. Interaction approach

Save state machine (per form):

```
idle ──edit──▶ dirty ──submit──▶ saving ──ok──▶ saved (2.5 s) ──▶ idle
  ▲              ▲                 │
  └──── edit ────┴───────error ◀───┘
```

- `isDirty` = current values vs baseline (last saved). Button always enabled except while pending (`aria-disabled`, keeps focus; action idempotent).
- Status text is honest and persistent: "Unsaved changes" → "Saving…" → "Saved · 12:04" (button reverts after 2.5 s; text stays until the next edit) → or "Couldn't save. Try again." Single `role="status"` element per form, never conditionally mounted.
- Button label swap via a stacked grid cell with a fixed min-width, so the button never changes width.

Validation: on blur per field once touched, on submit for all; errors clear as soon as the field changes. Form has `noValidate`; the Constraint Validation API plus `validation.js` are the source of truth (`user-invalid:` styles the CSS side). Failed submit: mark all touched, focus the first invalid field, announce "Fix 2 fields to save" — client guard in `onSubmit` so a client-side failure never enters the pending state (verify at implementation that `preventDefault` in `onSubmit` suppresses the `action` dispatch, else use a client wrapper action). Server `fieldErrors` merge into the same display path.

Profile: Name (`autocomplete=name`, required), Email (`type=email`, `inputmode=email`, `autocomplete=email`, required, format check), stacked on mobile; the director decides whether `md+` uses the classic left-rail/right-fields grid.

Notification toggles: data-driven list rendered by `Switch`; the whole row is the label (full-width tap target, `min-h-11`); description via `aria-describedby`; state must not be color-only (thumb glyph or On/Off text — director picks). Toggles participate in the batched Save rather than instant-apply, so the page has one save model; `useOptimistic` instant-apply is available as an alternative if the owner prefers.

Password: Current (`autocomplete=current-password`) and New (`autocomplete=new-password`), each with a show/hide `<button aria-pressed>` (≥44 px, does not move focus). Requirements list (≥10 characters; differs from current; not your email) ticks live and doubles as the blur error summary. Own submit "Update password"; success clears fields and announces.

Mobile: inputs `min-h-12 text-base` (16 px prevents iOS zoom); `SaveBar` is `sticky bottom-0` inside the form with `pb-[env(safe-area-inset-bottom)]`, translucent surface, shown only when dirty/pending/just-saved so it never permanently covers content; fields carry `scroll-mb-24` so focus-scroll clears the bar; `pointer-coarse:` enlarges hit areas; DOM order = visual order so the bar is last in tab order.

## 7. Motion budget (micro-motion only)

One easing (`--ease-out: cubic-bezier(.2,.8,.2,1)`), four durations: 120 ms color/opacity, 180 ms switch thumb, 220 ms error reveal and saved-label swap (check drawn via `stroke-dashoffset`), 260 ms mobile save-bar slide (`starting:` + `transition-discrete` for display-none reveal). Error reveal animates `grid-template-rows 0fr → 1fr` (no JS measuring). Every transition is under `motion-reduce:transition-none`; the check draw and bar slide become instant.

No ambient or continuous animation exists anywhere in this design — no scroll reveals, no hover lifts, no background motion — so constraint 1 is satisfied by construction. The single looping element is the pending spinner, which is mounted only while a request is in flight and unmounts on settle. Verification: `document.getAnimations().length === 0` in the live page at rest, in idle and after the saved revert, and the spinner absent from the DOM when not pending.

## 8. Accessibility commitments

Heading order h1 → h2 → h3; sections `aria-labelledby`; switch group in a `fieldset` with `legend`. Every input labeled with `autocomplete`; errors with `aria-invalid`, `aria-describedby` (hint + error), icon plus text; focus moves to the first invalid field. `focus-visible` 3 px ring token on every interactive element (Tailwind 4 bare `ring` is 1 px — use `ring-3`). Existing muted color passes AA (computed 4.9:1 light, 7.2:1 dark); new tokens must pass 4.5:1 text / 3:1 UI in both schemes. Targets ≥44 px. `color-scheme` retained so native controls match. No keyboard traps; Enter submits from any field; Space toggles switches.
