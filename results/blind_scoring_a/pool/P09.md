# Rendering architecture decision: Experience Constellation

## 1. What the repository is

- Next.js **16.2.12** App Router, React **19.2.8**, Tailwind **4.3.3**, plain `.jsx` (no TypeScript), `@/*` alias, Node 22.14 locally (Next requires >=20.9). `node_modules` is not installed; the lockfile contains **zero** graphics/animation libraries.
- A quiet personal portfolio: `app/page.jsx` is a Server Component rendering a header, `ProjectGrid` (static), and `SettingsPanel` (client form). Palette is five CSS variables in `app/globals.css` with a `prefers-color-scheme` dark variant; font is system Arial/Helvetica.
- `components/ConstellationData.js` already defines the 500 nodes: `{ id, label: "Node N", category }` across four categories (engineering, research, design, math). **There are no image URLs** — "logo/image nodes" has no asset source yet. The architecture below treats that as a first-class fact rather than a blocker.
- No `.claude/` in the repo; Impeccable and vendor skills (Pixi/three/GSAP/React Bits) are not installed locally.

## 2. Register: W (Expressive), with spectacle weighed and declined

The brief's words — interactive, drift, respond, regroup — trigger the spectacle check, so here is the explicit weighing. The constellation passes the S test locally: a realtime graphical system is the structural core of the section, and interaction materially changes it. I am still **declining S** as the register because: the host page is Q (dense, utilitarian, no motion anywhere else); the brief asks for *subtle* drift and treats selection/filtering as first-class, which makes this a browsable index, not an immersive world; and nothing in the brief asks for the unforgettable/experimental treatment that justifies shaders-for-their-own-sake, 3D, post-processing, or audio. So: **W** — motion serves one signature idea, the regroup — while the realtime core gets S-grade *performance architecture* (GPU instancing, strict pause discipline, frame budget) confined to the section. Concretely declined: WebGPU, 3D/camera, custom post-effects, a shader background behind the nodes, and any animation outside the canvas other than Tailwind transitions on chips.

## 3. The decision in one paragraph

Build a **dependency-free WebGL2 instanced-sprite renderer** (one shader program, one instanced VAO, one texture atlas, one draw call per frame) with a **Canvas2D fallback** driven by the same scene data, a **single JS simulation module** that owns every node transform (typed arrays: spring-to-target + low-frequency drift + pointer field), a **deterministic layout module** that produces target positions per view (constellation / grouped / filtered), and **React owning only the chrome and lifecycle** (filter chips, legend, selected-node panel, DOM tooltip and cluster labels, an accessible list). No engine, no ticker but ours, no new npm dependency. Estimated ~700–900 lines of new code, ~10–12 KB gzipped.

## 5. Substrate comparison — why no engine

**PixiJS 8.20.1** (published 2026-08-26) is the strongest substrate candidate and I verified it would work: `ParticleContainer` requires one shared base texture but writes each particle's own `texture.uvs` into the buffer (`particleData.ts`), so per-node atlas frames are fine; `dynamicProperties` can enable `color` for selection dimming; `autoDetectRenderer` tries WebGL first by default. It is rejected for this scope on evidence:
- **Hidden default loops.** `TickerPlugin` defaults to `autoStart: true, sharedTicker: false`; `Ticker.shared` and `Ticker.system` are lazily created with `autoStart = true` and `_protected = true`; `EventSystem._addEvents()` (reached from `setTargetElement` at init) calls `EventsTicker.addTickerListener()`, which adds to `Ticker.system` unconditionally — so `app.ticker.stop()` leaves a library rAF loop alive. `stop()` does work on protected tickers (only `destroy()` is a no-op), so it is controllable, but it is exactly the class of failure rule 1 exists for, and it would need three stops plus a test for each.
- **Weight.** `dist/pixi.min.mjs` is 819.5 kB (74 MB unpacked package) for a section that needs one textured-quad program. Tree-shaken size for a sprite-only build is UNVERIFIED; I would not bet a portfolio page's budget on it.
- Its scene graph, event system, text, filters and masks are unused here. Pixi becomes the right call if the section grows to thousands of nodes with in-canvas text, masks, or filters.

**three 0.185.1 + R3F 9.7.0 + drei 10.7.8**: 23 MB package and 3D machinery for 2D sprites; R3F's peer range is `react >=19 <19.3` against our 19.2.8, a fragile pin for a site that will upgrade React; drei `<Instances>` shares one material (per-instance atlas UVs need a custom shader anyway, per the agent's read of the drei docs); R3F's pause primitive is `frameloop="demand"/"never"` + `invalidate()` — no automatic offscreen pause (inferred from the docs; not a verified negative). Rejected.

**@pixi/react 8.0.5** (peer React >=19, pixi ^8.2.6) owns the render loop — a second loop owner. Rejected with Pixi.

**ogl 1.0.11** (what React Bits uses): a thin WebGL helper with no ticker. It would save ~100 lines of program/geometry/texture boilerplate at the cost of a dependency and its API churn; for one instanced program the trade is not worth it. Rejected, narrowly.

**DOM nodes (500 `<img>` with transforms)**: 500 composited layers with per-frame style writes for proximity — jank on laptops, worse on phones. Rejected for rendering; DOM is kept for everything textual and for accessibility.

**Canvas2D as primary**: viable on laptops, but 500 `drawImage` calls with per-node alpha/scale at DPR 3 on mid-range phones is where it gets marginal, and its minification quality is uneven. Kept as the **fallback** (WebGL2 unavailable or lost twice), driven by identical scene arrays so behaviour is the same.

**Worker + OffscreenCanvas**: per-frame JS here is under a millisecond, so there is nothing to move off the main thread; it would add pointer/resize/DPR plumbing, and Safari only got WebGL in OffscreenCanvas at 17.0 (caniuse; partial 2D-only from 16.2; BCD lists 16.4). Declined. **WebGPU**: no benefit for one draw call. Declined.

## 6. Architecture

**Ownership (one owner per concern)**
- Design director: the available `frontend-design` skill (Impeccable is not installed). It owns the section's visual thesis, typography, chip/panel design, atlas glyph styling, and final critique. This architect skill sets constraints only and is not loaded as a second director.
- Architect (this): register, rendering boundary, adopt-vs-build, performance architecture.
- Transform owner: `sim.js` — the only code that writes node x/y/scale/alpha. React never animates nodes; CSS never touches the canvas.
- Layout owner: `layout.js` — targets only; it never animates.

**Data and texture**
- Source: `components/ConstellationData.js` (500 items, 4 categories). Data is imported directly in the client component; no RSC payload duplication.
- Atlas: built at mount on a 2D canvas from the data — a monogram glyph per node (initials from `label`) on a category-tinted rounded tile — then uploaded once as one RGBA texture with mipmaps. Desktop: 64 px tiles on 2048×1024 (512 slots, 8 MB VRAM); mobile: 32 px tiles on 1024×512. The atlas module accepts an external spritesheet + frame JSON so real logos drop in later without touching the renderer.
- Palette: read `--foreground/--muted/--surface/--line` from `getComputedStyle` at mount and on `matchMedia('(prefers-color-scheme: dark)')` change; rebuild the atlas on change so the canvas follows the site's theme.

**Layout (`layout.js`)**: seeded PRNG for determinism across reloads. Views: *constellation* (golden-angle scatter with soft category zoning so regrouping reads as coherent motion), *grouped* (four phyllotaxis clusters at anchor points — overlap-free without iteration), *filtered* (matching nodes gather center, non-matching recede to alpha 0.15 / scale 0.6). Anchors and cluster label positions are exported so DOM labels sit on them.

**Simulation (`sim.js`)**: Float32Arrays for position, velocity, target, scale, alpha, frame index. Per frame: critically damped spring toward target (regroup), two-sine low-frequency drift with per-node phase (subtle; amplitude a few px), pointer field with smoothstep falloff (radius ~120 px desktop: slight displacement + scale to ~1.6x + brightening), hit-testing via a uniform grid rebuilt each frame (cell = 2× sprite size) for O(1) hover/tap queries. Cost is ~500 × 30 flops — negligible.

**Renderer (`gl-renderer.js`)**: WebGL2, `drawArraysInstanced` on a unit quad with per-instance attributes (x, y, scale, alpha, tint, atlas index → UV rect); one texture, premultiplied alpha, `preserveDrawingBuffer: false`, `powerPreference: 'low-power'` by default. Handles `webglcontextlost` (preventDefault, pause) and `webglcontextrestored` (recreate program/buffers/texture); second loss within a session → switch to `canvas2d-renderer.js`.

**React/Next boundaries**
- `app/page.jsx` (Server Component) renders `<ExperienceConstellation />` between the header and `ProjectGrid`.
- `components/constellation/ExperienceConstellation.jsx` is `"use client"`: heading, filter chips, "group by category" toggle, legend, selected-node panel, tooltip, cluster labels, and the accessible list. It loads the canvas with `next/dynamic(() => import('./ConstellationCanvas'), { ssr: false })` **from inside this client component** — the Next 16 docs state `ssr: false` is not allowed with `next/dynamic` in Server Components.
- SSR output is the full chrome plus a fixed-aspect placeholder (no CLS); the canvas hydrates client-side. Turbopack is the default for `next build` in 16; with zero third-party graphics deps there is nothing exotic to bundle.
- Controller API between React and the imperative core: `setFilter(category|null)`, `setGrouped(bool)`, `select(id|null)`; callbacks `onHover(id|null, x, y)`, `onSelect(id)`, fired only on change.

**Pause discipline (`loop.js`) — rule 1, unprompted**
- Running iff `intersecting && !document.hidden && !contextLost && !settled`. IntersectionObserver on the section (threshold 0) + `visibilitychange` + a "settled" state (all springs at rest and drift disabled → render on demand only).
- Pausing cancels the pending rAF and detaches pointer sampling; resuming resets the clock so there is no catch-up jump. There is no library ticker to forget — that is a deliberate consequence of the substrate decision. Browsers also throttle rAF in hidden tabs, but we do not rely on that (the MDN statement was not re-fetched successfully; irrelevant to the design since we stop ourselves).

**Degradation (measured, not guessed)**
- At mount: `prefers-reduced-motion` → no drift, no pointer displacement, regroup completes as a 300 ms crossfade-plus-move; `pointer: coarse` → no proximity hover, tap selects, 44 px minimum hit target; DPR capped at 2 (desktop) / 1.5 (coarse pointer); smaller atlas tiles on small screens. `navigator.deviceMemory` is Chromium-only (Chrome 63+, never Firefox/Safari), so it is a hint only, never a gate.
- At runtime: a frame-time governor steps down tiers when p90 frame time exceeds ~20 ms over a 2 s window: disable drift → lower DPR → cull to a representative ~250 nodes (accessible list still shows all 500 with the culled ones marked). All 500 render by default on every device; culling is the last tier, not the mobile default.

**Interaction and accessibility**: hover highlight + DOM tooltip (label, category); click/tap → single select → panel; chips are real buttons with `aria-pressed`; canvas gets `role="img"` and a live-region summary ("142 of 500 shown · Design"); a "Browse as a list" disclosure exposes all nodes as DOM for keyboard and screen-reader users. Text is never rasterized into the canvas.

**Budgets**: ≤ 12 KB gzipped new JS; 0 new dependencies; 1 draw call/frame; < 1 ms JS per frame on a 2020-class laptop; ≤ 8 MB VRAM desktop / 2 MB mobile; zero layout shift.

## 7. Verification protocol (rule 2 — actual conditions, not proxies)

Run in a real browser (Claude Browser or Playwright) with a debug hook exposing the frame counter and loop state:
1. Scroll the section out of view → frame counter must not advance for ≥ 1 s and `state.running === false`; scroll back → advances again.
2. Background the tab by activating another tab in the same window (real `document.visibilityState === 'hidden'`, not a flipped property) → counter frozen; re-activate → resumes with no position jump.
3. Mobile emulation (390×844, DPR 3, coarse pointer): measure frame-time p90 from the hook; confirm hover path is inert and tap selects.
4. Force WebGL2 unavailable (Chromium `--disable-webgl` or a `getContext` override) → Canvas2D fallback renders the same layout; simulate context loss with `WEBGL_lose_context` → restore path works.
5. Emulate `prefers-reduced-motion: reduce` → no drift, regroup still completes.
6. Filter and group transitions: assert every node reaches its target within the spring settle time and that non-matching nodes are excluded from hit-testing.
Anything not observed working under these exact conditions will not be claimed.
