## Architecture decision: image refraction layer for `jordan-lee-site`

### What the repo actually is

Next.js 16.2.12 App Router, React 19.2.8, Tailwind 4.3.3, no animation/GL dependencies, `node_modules` absent. Three findings constrain the design more than the brief does:

1. **There are no images.** `components/ProjectGrid.jsx` is a *server component*; each card is `<a href="#project-N">` wrapping an `aria-hidden` `<div data-project-media>` painted with a CSS gradient. A refraction shader needs pixels to refract, so real `<img>` elements have to be introduced (same-origin or CORS-enabled — GL can't sample a tainted image).
2. **"Opening a project" has no destination.** The `#project-N` hashes point at nothing; no `/projects/[id]` route, no dialog. The transition layer therefore has to live somewhere that survives whatever the destination turns out to be.
3. `components/ConstellationData.js` (500 nodes) is imported by nothing. Unrelated; leave it.

### Register: W (Expressive), with spectacle explicitly declined

"High-end", "dramatic", "shader-like" are Spectacle signals, so I weighed S. Declined: the brief pins text, layout, a11y, SEO and responsiveness to normal DOM and scopes motion to the images. The graphical system is *not* structurally central — the page stays a semantic grid, and interaction changes only the pictures. Making the grid a WebGL scene would violate the constraint outright. The image layer gets S-grade rendering discipline (GPU, on-demand, DPR-aware), but the page is W.

### Recommendation: one shared, transparent, on-demand WebGL2 overlay — no dependencies

**Rendering model.** A single `position: fixed; inset: 0; pointer-events: none; aria-hidden` canvas (backing store = viewport × min(DPR, 2)) with one WebGL2 context, one program, one unit quad. Each registered `<img>` is drawn as a screen-space quad at its `getBoundingClientRect()` via `gl.viewport` + `gl.scissor`. The rect is read inside the rAF so scroll stays in sync; a passive scroll listener just requests a frame.

**Overlay, never swap.** The DOM `<img>` is never hidden. At rest the canvas paints nothing; while the pointer is active over a card (or a transition runs) the GL quad fades in (~100 ms) *on top of the identical image*, and fades out when the field relaxes. This removes the whole load-state/readiness/flash machinery of the usual "hide the img once GL is ready" pattern, and it means *every* failure mode — no WebGL2, context loss, texture CORS failure, reduced motion, JS off — degrades to the unmodified site. SEO and the accessibility tree see the same `<img src alt>` in every state.

**Shader model.** Single pass, no framebuffers. A uniform array of the last ~12 pointer samples `(x, y, age)` drives an analytic height field; refraction = UV offset along its gradient; dispersion = R/G/B sampled at slightly different offsets; optional glint from the field's normal. Relaxation is age-based, so the loop has a deterministic stop condition. A rounded-rect SDF mask (radius read from the img's computed `border-radius`) keeps the square quad from overpainting the card's `rounded-lg` corners; premultiplied-alpha blending onto a transparent clear. If the design director later wants persistent fluid (vorticity), a ping-pong FBO is a bounded upgrade, not a rewrite.

**Transition model.** Same program, `uProgress` 0→1. On click (GL available, motion allowed): `preventDefault`, tween the quad's rect from the card to the target rect while distortion crests and settles, then `router.push`. Because the layer mounts in `app/layout.jsx`, it persists across the navigation; the destination hero `<img>` registers under the same project id and the in-flight quad hands off to its rect — shared-element continuity with no snapshotting. Works identically if "open" becomes an in-page dialog (only the target rect source changes). Keyboard Enter fires the same anchor click; reduced-motion or no-GL users get the plain link.

**Client boundary (smallest that works).** `ProjectGrid` stays a server component. Three small client pieces: `MediaFXLayer` (once, in layout: canvas, GL, registry, loop, gates), `ProjectMedia` (leaf: renders the real `<img>` with `alt`/`loading="lazy"`/`decoding="async"`/`sizes` — or `next/image` — keeps the gradient as loading background, registers its element), and `ProjectCard` (thin `next/link` wrapper owning the click; title/summary still passed as server-rendered children). Communication through a module-level registry, not React state — the loop reads rects at 60 Hz and must not cause renders. Textures are uploaded from the already-decoded `<img>` element after `decode()` (so `currentSrc`'s right-sized bytes are reused, no second download) and deleted on unregister.

**Pause rules — designed in, not bolted on.** Render-on-demand with three gates: (a) *activity* — the loop runs only while a pointer sample is younger than the decay window or a transition is in flight; (b) *viewport* — an `IntersectionObserver` per registered img; offscreen quads are skipped, and with zero visible images pointer input is dropped and no frame is scheduled; (c) *document* — `visibilitychange`/`pagehide` cancel the rAF, resuming only to finish an interrupted transition. `webglcontextlost` → stop and let the DOM images carry the page.

**Footprint.** Roughly 300–400 lines including both shaders, ~4–6 kB gz, zero new dependencies, one WebGL context regardless of project count.

### Why not the nearest alternatives (fit gate)

| Option | Verdict | Why it loses here |
|---|---|---|
| React Bits *Ripple Distortion* (ogl), *Grid Distortion* (three); Paper Shaders 0.0.80 `lens-distortion` / `water` / `fluted-glass` | **Reference-only** | All verified canvas-per-instance with their own WebGL context and no `<img>` in the DOM. Eight cards = eight contexts against a 16-per-page cap (8 on Android) — a 12–16 project grid starts evicting. None can expand past its own box for the open transition, and that transition would still be custom GLSL, so the dependency saves nothing. Ripple Distortion's parameter surface (dispersion, glint, fade, reduced-motion) is the best *look* reference; Paper Shaders' IO + `visibilitychange` pausing is the right behavioural reference. |
| Fancy Components, SmoothUI | Checked — nothing applicable | DOM/Motion/SVG components only. |
| curtains.js 8.1.6 | Reference-only | Architecturally the closest thing that exists (shared canvas, DOM-synced planes) — it validates the approach — but last published May 2024 and its successor is WebGPU-only (Safari 26/iOS 26 only, Firefox partial). Adopting a dormant dependency to avoid ~200 lines of GL is a bad trade. |
| OGL 1.0.11 | Adapt — declined narrowly | The real runner-up: 8 kB core, no ticker, would save ~100 lines of program/texture/uniform boilerplate. Declined because our GL surface is one program, one quad, N textures, viewport/scissor placement — OGL's Camera/Transform/Mesh layers have nothing to abstract. Revisit if a second effect type or real geometry appears. |
| Three 0.185 + R3F 9.7 + drei 10.7 `<View>` | Reject | Solves the same multi-view-on-one-canvas problem with a scene graph, camera and second reconciler for two screen-space shaders; ~10× the bundle; R3F defaults to `frameloop="always"` so constraint 1 becomes an audit instead of a property of the design. Justified only for a real 3D system — register is W. |
| Pixi 8.20 `DisplacementFilter` | Reject | Built-in displacement is tempting, but `autoStart: true`, ~400 kB, own scene graph and event system, and displacement-map look is lower fidelity than analytic refraction + dispersion. |
| SVG `feDisplacementMap` / `feTurbulence` (React Bits *Glass Surface* style) | Reject, including as fallback | Zero deps but CPU-rasterized on large surfaces and poor on Safari; no real refraction; cannot produce a shader-like open transition. A janky fallback is worse than the clean image — fallback is "no effect". |
| View Transitions (`<Link transitionTypes>` since Next 16.2; React `<ViewTransition>` is canary-only) | Complement, not replacement | Snapshot crossfade/morph, not a shader — can't deliver the image transition. Could later animate the *text/layout* of the open while GL owns the image. Not needed for v1. |
| Per-card canvases blitting from one shared context; OffscreenCanvas + worker; WebGPU | Reject | Per-card copy per frame and still box-bound; worker messaging for eight quads is overhead without a bottleneck; WebGPU excludes most Safari/Firefox installs today. |

### Verification plan (actual conditions, not proxies)

Dev-only counter `window.__mediaFX = { frames, active, visible }`, then in a real browser: scroll the grid fully out of view and wave the pointer for 3 s → `frames` unchanged; switch to *another real tab* mid-hover and come back → no frames rendered while away; hover then hold still → loop halts within the decay window; emulate `prefers-reduced-motion: reduce` → no canvas mounted, click navigates normally; launch Chromium with WebGL disabled → grid pixel-identical to baseline; accessibility-tree snapshot before/after identical; SSR HTML (curl) contains the `<img src alt>`; CLS delta 0 (canvas is out of flow).

### Assumptions to confirm (none block the architecture)

- Real project images will be provided, same-origin or with CORS headers (`crossOrigin="anonymous"` on the img if remote).
- "Opened" means a `/projects/[id]` route (my assumption) or an in-page dialog — same design either way.
- Whether images are decorative relative to the `<h3>` (`alt=""`) or content-bearing (descriptive alt) is a content-owner call.
