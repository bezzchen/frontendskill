## 2. Proposed architecture

### 2.1 Layering — React owns the tree, Anime owns transforms

React renders the semantic DOM once and manages exactly one piece of state: the active view (`experience | projects`). All motion lives in a framework-free controller module driven by Anime.js; React never re-renders to move things. Communication is one-way and narrow: React calls `controller.setView(view)`; the controller never touches React state.

```
components/
  ExperienceSystem.jsx            "use client" — markup, tabs, view state, boots controller in useEffect
  experience-system/
    controller.js                 mountExperienceSystem(rootEl) -> { setView, revert } — createScope, modes, drag
    layouts.js                    pure math: orbitAnchor(item, t, rect), structuredSlots(view, rect, cardSize)
    constants.js                  tuning knobs: radii, angular speeds, springs, breakpoints, durations
```

`layouts.js` is pure (no DOM), so anchor math is unit-testable later. Item data stays in `ExperienceSystem.jsx` for now (could move to `data/experience.js` when real content lands), each item gaining `role/dates/href/logo` fields.

### 2.2 Progressive enhancement — today's grid is the baseline

The current grid markup remains the SSR/no-JS/reduced-motion truth. The controller *lifts* items into an absolutely-positioned "stage" only when the orbital mode's conditions hold. First paint is always the clean grid; there is no layout shift on mobile, and no-JS visitors lose nothing.

DOM contract (per item — this nesting is the heart of the design):

```
<section>                         heading + tablist (React)
  <div data-stage>                relative container; explicit height only in orbital mode
    <div data-hub>                central project object (absolute center; hidden in structured modes)
    <div data-orbit-node>         transform written ONLY by the layout/follow loop
      <button data-item>          transform written ONLY by createDraggable; stays a real button
        logo, label, detail block
```

**Single-writer principle:** two nested wrappers give every transform exactly one owner, so orbit motion and dragging never fight over `translate`. The element's on-screen position is always `anchor (outer) + drag offset (inner)`. On release the inner offset springs back to `0,0`, so the item rejoins its orbit *wherever the orbit has drifted to in the meantime* — the "system heals" for free, with no reconciliation code.

### 2.3 Mode system — `createScope` with `mediaQueries`

One `createScope({ root, mediaQueries })` instance is the backbone:

```js
mediaQueries: {
  orbital: "(min-width: 1024px) and (prefers-reduced-motion: no-preference)",
  reduced: "(prefers-reduced-motion: reduce)",
}
```

Scope constructors re-execute automatically when a query flips (window resized, OS motion setting changed), reverting the previous mode's animations and draggables. This gives us mode switching with zero hand-rolled listener bookkeeping, and `scope.revert()` in the `useEffect` cleanup handles unmount and StrictMode re-runs — the same `revert()` contract `IntroFade.jsx` already uses.

Three modes fall out:

- **Orbital** (≥1024px, motion OK): stage gets a fixed height (~34rem), items lift to absolute, orbit loop + draggables active. Touch is allowed here (iPad landscape gets the full experience — `createDraggable` handles pointer and touch natively and sets `touch-action: none` on drag targets, which is safe because the stage is one section of a scrollable page, not the whole viewport).
- **Structured-animated** (<1024px, motion OK): items stay in normal flow; view toggles animate via FLIP (measure old rects → apply new order/emphasis → invert with transforms → `animate` to zero with `stagger`). No absolute positioning, so natural document height and uninterrupted page scrolling — vertical pan is never stolen from the scroller because no draggables exist in this mode.
- **Reduced-motion** (any width): today's static grid; view toggle swaps emphasis instantly (or with a ≤150ms opacity-only crossfade). No orbit, no drag, no inertia.

### 2.4 The motion engine inside orbital mode

- **One clock:** a single `createTimer({ onUpdate })` advances time and computes each item's *anchor* — no per-item RAF loops, no layout reads in the hot path (container rect cached, refreshed by `ResizeObserver`).
- **Anchors, not positions:** `orbitAnchor(item, t)` = center + ellipse(radiusᵢ + breathingᵢ(t), phaseᵢ + ωᵢ·t), with per-item radius, angular velocity ω (slow: one revolution per 60–120s, alternating direction), phase spacing to avoid overlap, and a slow sine "breathing" on the radius plus a ±3px drift wobble. Vertical squash (~0.72) plus scale/z-index modulated by sin(phase) gives cheap depth. This is the "loose" in loosely orbiting — deterministic, but never static.
- **Smoothed following:** each orbit-node gets a `createAnimatable` (x, y, scale with ~350–500ms ease-out response). The timer writes anchor targets into the animatables; the animatable's lag produces organic trailing motion and — critically — makes every state change (orbit ↔ structured slots, resize, post-drag rejoin) converge smoothly through the exact same pipeline. There is no special-case transition code: changing state = changing where anchors point.
- **Dragging:** one `createDraggable` per item `<button>`, `container: stage` with soft `containerFriction`, release inertia from the built-in velocity model, and `releaseEase: createSpring({ stiffness ~120, damping ~14 })` pulling the inner offset home. `onGrab` suspends that item's anchor-following and raises z/scale; `onSettle` resumes it.
- **Click vs drag disambiguation:** items are real buttons (and will get hrefs/detail actions), so the controller tracks displacement between `onGrab` and `onRelease`; beyond ~6px it suppresses the trailing `click` via a capture-phase handler. Below the threshold the click proceeds normally.
- **View changes in orbital mode:** `setView('experience')` retargets anchors — selected items head to `structuredSlots(...)` (a computed row of enlarged cards, detail block crossfading in), unselected items shrink slightly and keep orbiting a hub that eases toward the stage's edge. Slot math is computed (measured card size + container width), not DOM-measured mid-flight, since cards are uniform. Draggables on docked items are `disable()`d (structured means *clean*); orbiting items stay grabbable.

### 2.5 Lifecycle, performance, a11y

- Transforms and opacity only; `will-change: transform` applied while the system is live. 6 items + hub = trivial per-frame cost, O(n) with zero DOM reads.
- `IntersectionObserver` pauses the timer when the section is off-screen; Anime's engine already pauses on hidden tabs (`engine.pauseOnDocumentHidden` default).
- DOM order never changes, so tab order is stable regardless of visual position; focus ring must not be clipped (`overflow: visible` on stage). On focus, the focused item's ω lerps to 0 (it holds still while focused — also nice for hover). Tabs get `aria-pressed`/`tablist` semantics; hit targets stay ≥44px.
- Hydration-safe: no `window` access outside effects; all mode detection lives inside the scope.

## 3. Interaction model (state machine)

States: `view ∈ {none, experience, projects}` × `mode ∈ {orbital, structured-animated, reduced}`.

| # | Trigger | Orbital (≥1024px) | Structured (<1024px) | Reduced |
|---|---|---|---|---|
| 1 | Load | Grid paints (SSR) → items lift and drift from their grid rects into orbit, staggered (~900ms) — the intro itself demonstrates "same elements, two states" | Static grid, `IntroFade`-style entrance | Static grid |
| 2 | Idle | Slow elliptical orbit around central project hub; breathing radii; depth scale/z | — | — |
| 3 | Hover/focus item | Item's orbit eases to a halt, slight scale-up + label emphasis; resumes on leave | Standard hover style | Standard |
| 4 | Grab + drag | Scale ~1.05, z-boost, free drag within stage (soft edges); anchor-follow suspended | n/a (no draggables) | n/a |
| 5 | Release | Inertia glide → spring back to the (moved) orbit anchor; system heals | n/a | n/a |
| 6 | Select "Experience"/"Projects" tab | Selected 3 FLIP into a clean structured row with detail crossfade; other 3 shrink and keep orbiting the offset hub; docked items' drag disabled | FLIP re-emphasis in flow: selected group expands to full cards, other collapses to a compact chip row — same elements, reorganized, staggered ~450ms | Instant swap (or ≤150ms fade) |
| 7 | Re-click active tab (or "constellation" affordance) | Return to full orbit (state 2) | Collapse back to mixed grid | Instant |
| 8 | Resize / motion-pref change | `createScope` reverts and reconstructs the correct mode; draggables `refresh()`; anchors converge via the follow pipeline | same | same |

## 4. Open questions before implementation (with proposed defaults)

1. **Is orbit the initial state or a third "all" tab?** Proposed default: orbit is the ambient initial state; selecting a tab structures it; re-clicking the active tab releases back to orbit.
2. **What is the central project object?** Proposed default: a hub card for the featured project (`project-1`) — it can later become interactive (drag an item onto it = focus swap) but that's explicitly v2.
3. **Breakpoint for orbital mode:** proposed `min-width: 1024px` (includes landscape tablets, which handle touch-drag well); happy to gate on `pointer: fine` instead if you want phones/tablets fully excluded.
4. **Should released items *throw* along their orbit** (release velocity nudges orbital phase)? Delightful but tuning-heavy — proposed as v2.

Verification plan once implemented: manual matrix (desktop pointer, iPad touch, small phone, `prefers-reduced-motion`, dark mode), StrictMode double-mount, resize across the breakpoint mid-drag, and a Playwright smoke test asserting the SSR grid renders and the tab toggle updates `aria-pressed` + visible emphasis.

result: Proposal delivered for RUNDIR (Next 16 / React 19 / Anime.js 4.5.0 portfolio) — a single-writer, two-layer transform architecture (orbit anchors via createTimer+createAnimatable, drag offsets via createDraggable, responsive modes via createScope mediaQueries) with a three-mode interaction model (orbital desktop, FLIP structured mobile, reduced-motion static) and 4 open questions; no code written yet.
