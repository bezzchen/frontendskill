## Inspection findings

**Stack:** Next.js 16.2.12 (app router), React 19.2.8, Tailwind CSS 4.3.3 (v4 CSS-first — no tailwind.config, tokens live in `app/globals.css`), plain JavaScript with `@/*` path alias. No test setup, no animation library, no other runtime deps.

**Page structure:** `app/page.jsx` is a quiet editorial portfolio (header → `ProjectGrid` → "Account settings" section, `max-w-2xl`, `aria-labelledby`). The settings UI is one client component, `components/SettingsPanel.jsx`. `ConstellationData.js` is unused by the settings flow. Design language: warm neutrals via CSS vars (`--background/--foreground/--muted/--surface/--line`), light+dark via `prefers-color-scheme`, Arial, generous whitespace.

**Current defects/gaps in `SettingsPanel.jsx`:**
- Password input has **no label** (placeholder only) and no confirm/visibility affordances — a11y failure.
- Heading hierarchy is broken: "Profile"/"Notifications"/"Password" are `h2` nested under the page's `h2` ("Account settings") — should be `h3`.
- `saved` flag is set once and **never resets** — edit after save still shows "Saved"; no dirty tracking, no saving/pending state, no double-submit guard.
- Zero validation (name/email/password), no error rendering, no `aria-invalid`/`aria-describedby`.
- Notifications is a bare native checkbox, not a switch; single toggle only; small touch target.
- Inputs are uncontrolled (`defaultValue`), so dirty state can't be derived; no focus-visible treatment beyond browser default, no motion, no reduced-motion consideration, no mobile-specific behavior.

## Proposed architecture

**Dependency decision: add nothing.** Every interaction this page needs — switch thumb slide, button state morphs, error slide-in, sticky save bar reveal — is comfortably covered by CSS transitions/keyframes plus small React state machines. Tailwind v4's `@theme` lets me define easings/keyframes as first-class tokens. An animation library (motion/framer) costs ~30–50 kB gzip and React-19 peer-dep surface for zero capability we need; exit animations (the one thing CSS makes awkward) are handled with `data-state` attributes + `transitionend`/timeouts. Staying dependency-free is the production-ready call for a repo this lean.

**File layout** (JS, matching repo conventions):

```
components/
  SettingsPanel.jsx        → orchestrator: form state, sections, submit flow
  settings/
    Field.jsx              → label + description + input + error slot; wires id/aria-describedby/aria-invalid
    Switch.jsx             → <button role="switch" aria-checked> with CSS-animated thumb
    PasswordField.jsx      → labeled input + show/hide toggle + requirements hint list
    SaveBar.jsx            → save button states + status live region; sticky on mobile when dirty
lib/
  settings.js              → pure validators + async saveSettings() stub (single swap point for a real API)
app/globals.css            → extend tokens: --accent, --danger, --success (light+dark), focus ring, easings, keyframes, reduced-motion guards; swap Arial → system-ui stack
app/page.jsx               → minor: widen settings section to max-w-3xl for a two-column settings layout
```

**State model (in `SettingsPanel`):**
- Controlled `values` + a `savedValues` snapshot; `dirty` is *derived* by comparison (plus non-empty password fields), never stored — eliminates the stale-"Saved" class of bug.
- `status: "idle" | "saving" | "saved"`; submit → validate all → if clean, `saving` (await `saveSettings()`, ~700 ms simulated latency), → `saved` (auto-decays to `idle` after ~2.5 s; any edit cancels it immediately); snapshot updates on success. `aria-busy` + guard against double submit.
- `errors` map + `touched` set. Validation timing: **on blur first, then re-validate on every change once a field has erred** ("reward early, punish late"). On submit: validate all, focus first invalid field, announce count via the live region.
- Rules: name required (≥2 chars); email required + format; password optional but if filled → min 8 chars + confirm match.

## Interaction & visual approach

**Layout:** one `--surface` card with internal `border-t` dividers; each section becomes label+description column left, controls right (≥`sm`), stacking on mobile — the Stripe/GitHub settings idiom, which reads as intentional rather than a bare stacked form. Headings fixed to `h3` with one-line muted descriptions.

**Inputs:** consistent 40–44 px height; border `--line` → hover darkens → focus shows 2 px `--accent` ring with offset; error state swaps to `--danger` ring + inline message that slides/fades in (150–200 ms, `motion-safe:` only). `autocomplete` attributes throughout (`name`, `email`, `new-password`).

**Notification toggles:** expand to three realistic rows (email notifications, product updates, security alerts — scope call, easy to veto) — each a full-width tappable row (label + muted description + switch), whole row toggles. Switch: 44 px hit area, thumb slides with a slight ease-out overshoot, `aria-checked` color shift to `--accent`, Space/Enter keyboard support.

**Password section:** New + Confirm fields, per-field show/hide toggle (`aria-pressed`), a small requirements checklist that ticks as criteria are met (visual only; described once via `aria-describedby` to avoid live-region chatter). Left out of "dirty" until non-empty; cleared after successful save.

**Save state:** button renders idle ("Save changes"), disabled-ish when clean (via `aria-disabled` + handler guard, so it stays in the tab order, paired with "No unsaved changes"/"Unsaved changes" helper text), saving (inline spinner + "Saving…"), saved (check icon flash). One polite live region announces "Saving changes… / Changes saved / N fields need attention."

**Mobile:** below `sm`, a save bar docks sticky to the viewport bottom **only while dirty** (translate-y reveal, `backdrop-blur`, `border-t`, `env(safe-area-inset-bottom)` padding) so save is thumb-reachable on a long form; all touch targets ≥44 px; no horizontal scroll at 375 px.

**Accessibility & motion:** every animation gated behind `prefers-reduced-motion`; focus-visible rings everywhere; contrast of new `--danger`/`--accent` tokens verified ≥4.5:1 in both schemes (and I'll re-check `--muted`, which sits near the 4.5 line today). Font swaps Arial → `system-ui` stack (free rendering upgrade, zero webfont cost, keeps the editorial tone).

**Verification plan for the implementation phase:** `npm install` + `npm run build` must pass; browser pass at 375/768/1280 in light + dark; keyboard-only walkthrough; reduced-motion spot check.

Considered and rejected: React 19 form actions/`useActionState` (controlled inputs win here because dirty-tracking and per-field validation need the values anyway; `saveSettings()` isolation keeps a later server-action swap trivial), TypeScript migration (needless churn for this task), and any component library (would fight the existing hand-rolled aesthetic).

result: Repo inspected (Next 16/React 19/Tailwind v4, single-file SettingsPanel with a11y and state bugs); proposed a zero-dependency architecture — 4 new subcomponents + validators lib, derived-dirty state machine, blur-then-change validation, CSS-token motion, switch-based toggles, sticky mobile save bar — awaiting go-ahead to implement.
